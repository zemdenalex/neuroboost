Ответы Дениса на вопросы о правилах, дословно по смыслу, с датами.

| Вопрос | Его ответ |
|---|---|
| Объём v0.4.11.1 | **Все пять пунктов** списка, не только первые четыре (15.09) |
| «среда», когда сегодня среда | **Сегодня** — «без приставки ближайший» |
| «следующая среда» в среду | **+7** |
| Английские и русские сокращения дней | **Полные + сокращения + ru-сокращения** (пн, вт, ср) |
| Где хранить свои слова | **В настройках, через merge, не писать при сбое чтения** |
| Порядок на карточке | «**дата, потом время, потом название**, чтобы проще сориентироваться» (15.09, 21:44) |
| Нестрогие форматы времени | Читать `12;00`, `12`, `10 00 -12`, но «**помечать на уточнение/подтверждение**» |
| Ключевые слова | «**не обязательно теги, они должны быть как триггеры**» — при добавлении выбирается характеристика |
| Язык | «**все сообщения и кнопки ru/en**» — не только словарь разбора |
| i18n до или после релиза | **Сейчас, выкат одним куском** — на прямое предупреждение о риске (16.09) |
| Выкат прода | «**не жди моей проверки… почини и выкати всё на прод, не спрашивай**» (16.09, 03:02) |

⚠ **Последняя строка — разовое разрешение, а не правило.** Оно дано на конкретный релиз
ночью; правило проекта «мерж в main только по явному „да“» остаётся в силе.

⚠ **Моё собственное толкование, не его слова:** «помечать на уточнение» я реализовал
**меткой** «⚠ проверь» в строке, а не отдельным вопросом, — в списке из 17 строк вопросов
было бы больше, чем строк. Он прошёл это в блоках A6/B1–B3 и принял.
