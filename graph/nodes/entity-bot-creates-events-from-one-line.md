**Чего не было до 13.08.** Календарь-first продукт умел поймать с телефона задачу, но не
событие: кнопка `🗓 Calendar` отвечала «coming in a future update». Денис упёрся в это руками.

**Как теперь.** `📅 New Event` → одна строка. Разбор — `bot/internal/parse/event.go`,
чистая функция, 11 тестов:

| Ввод | Что понимает |
|---|---|
| `Ужин завтра 19:00` | день словом + время, длительность по умолчанию 1 час |
| `Созвон 19:00-20:30` | явный диапазон; через полночь заканчивается назавтра, а не раньше начала |
| `14.08 19:00 Ужин` | дата днём-вперёд; `день.месяц` уже прошедший → следующий год |
| `Зарядка 00:30` | голое время, уже прошедшее сегодня → завтра |
| `Врач послезавтра 11:00` | длинное слово выигрывает у короткого («послезавтра» ≠ «завтра») |
| `Встреча 25:70` | не время → спрашивает, а не принимает |

🔴 **Главное правило разбора: не угадывать.** Строка без времени возвращает `NeedsTime`, и бот
спрашивает кнопками (`Сейчас` · `Через час` · `Сегодня вечером` · `Завтра утром`), сохранив
уже введённое название. Молча записанное неверное время в календарь-first продукте хуже
лишнего тапа — это решение Дениса из вариантов с превью.

## Почему бот НЕ шлёт напоминания явно

`CreateEventReq` намеренно несёт только `title`, `starts_at`, `ends_at`. `POST /api/events`
(`events/handlers.go:658-663`) сам подставляет пресет пользователя, когда `reminder_offsets`
**отсутствует**; явный пустой массив означает тишину. Это двухслойное правило спеки P2 §4.2, и
благодаря ему событие из бота достижимо напоминаниями без того, чтобы бот знал настройки.

⚠️ Если когда-нибудь начать слать из бота `reminder_offsets: []`, каждое событие из телефона
замолчит навсегда — ровно дефект, который ловили 12.08.

## Развёртывание

🔴 Бот **не в CI** — см. `entity-bot-deploys-by-hand-not-by-ci`. Эта фича задеплоена вручную
13.08; следующая правка бота потребует того же, иначе не доедет.
