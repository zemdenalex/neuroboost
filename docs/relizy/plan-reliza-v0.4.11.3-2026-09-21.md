## Почему срез именно здесь

Денис 21.09: выпустить сначала то, что он прошёл руками 18-го, а новое (повторяющиеся
задачи, статистика, сегодняшние починки) — следующим релизом, после перепроверки.

🔴 **Дробить по миграциям было нельзя, и это надо знать.** Все пять миграций (17–21)
приехали **одним днём, 18.09**. Любой срез, включающий этот день, несёт их все; срез до
него теряет починку snooze, ради которой релиз и затевается. Вывод на будущее: если версия
задумана отдельным релизом, её миграции обязаны быть отделимы — иначе версии это только
названия.

Коммиты 20–21.09 (10 штук): создание повторяющихся задач, `PressedDay`, человеческие тексты
ошибок, вопрос про запятые, экран «Сегодня» по-русски, кнопки повтора и долбёжки.

повторить дефект, который Денис поймал 20.09 проходом по чеклисту.

## Миграции 17–21 — что делает каждая

| № | Что | Опасность | Откат |
|---|---|---|---|
| 000017 | `reminder.nag_count`, `task.event_id`, таблицы `task_occurrence`, `task_nag` | 🟡 `CREATE TABLE IF NOT EXISTS task_occurrence` — форма из gotcha 18. **Проверено на боевой БД: таблицы с таким именем нет**, значит примет свою | down есть |
| 000018 | `ALTER TABLE task DROP COLUMN IF EXISTS event_id` | 🟢 Единственный DROP в наборе, и он отменяет колонку, которую **добавила 000017 в тот же день**. На проде её сейчас нет; после 17+18 её не будет снова. Данных в ней не было нигде | down возвращает пустую колонку |
| 000019 | `reminder.answered_at` + индекс | 🟢 Аддитивная. Это и есть починка snooze | down есть |

## Порядок выката

1. **Бэкап боевой БД** и проверка, что он читается (`pg_restore --list`), — до мержа.
2. `git status` на хосте прода — gotcha 20: ручные правки на сервере ломают `git pull`.
3. Мерж `release/v0.4.11.3` → `main`. Fast-forward возможен (`main` — предок среза).
4. CI сам выкатывает API и веб; миграции применяются на старте API.
5. **Проверить:** `schema_migrations = 21`, `dirty = false`, `/api/health` отвечает.
6. **Прод-бот руками** (gotcha 19, CI его не выкатывает):
   `/opt/neuroboost-bot-prod`, `git archive --prefix=src/ main:bot | ssh …`,
   `docker compose up -d --build bot`. Контейнер `neuroboost-prod-bot`.
7. Тег `v0.4.11.3` на `main` постфактум.

## Если пойдёт не так

- **API в crash-loop, `dirty = N`** — gotcha 18: доложить недостающее, затем
  `UPDATE schema_migrations SET version = N-1, dirty = false`, перезапустить.
- **Откат кода** — `main` вернуть на `3d1e152` (v0.4.11.2) и выкатить. ⚠ Миграции при этом
  **не откатываются сами**: схема 21 совместима с кодом 11.2 по всем добавленным колонкам
  (они nullable либо с DEFAULT), кроме `task.event_id` — её 11.2 не читает.
- **Бот** — вернуть `src.bak-<дата>` и пересобрать.
