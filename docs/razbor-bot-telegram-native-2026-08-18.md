## 1. 🔴 Ворота: библиотека старше продукта

`bot/go.mod` → `go-telegram-bot-api/v5 v5.5.1`. Это **Bot API ~6.1, лето 2022**.

Проверено с положительным контролем (искомое, которое обязано найтись, — находится):

| Символ в `types.go` библиотеки | Найдено |
|---|---|
| `InlineKeyboardButton` (контроль) | 🟢 4 |
| `SwitchInlineQuery` (контроль) | 🟢 4 |
| `WebAppInfo` — Mini Apps | 🔴 0 |
| `KeyboardButtonRequestUser` / `RequestUsers` — выбор контакта | 🔴 0 |
| `Checklist` — нативные чеклисты | 🔴 0 |
| `CopyText`, `MessageEffect` | 🔴 0 |
| `UsersShared`, `WebAppData`, `ChecklistTasksDone` — **входящие** | 🔴 0 |

🔴 **Лазейка `MakeRequest` односторонняя.** `bot.MakeRequest(endpoint, Params)` экспортирован
(`bot.go:95`), то есть **отправить** `sendChecklist` можно уже сегодня. Но `GetUpdatesChan`
(`bot.go:431`) отдаёт `[]Update` — **уже разобранные структуры**, и в `Update` нет ни новых
полей, ни `json.RawMessage`-заглушки. Значит галочку, поставленную в отправленном чеклисте,
бот **не увидит**. Отправка есть, приём — нет; а ценность чеклиста ровно в приёме.

⚠ **Тихая потеря переписывания, которой не было в списке:** v0.2.1 стоял на **telegraf 4.16.3**
(`_legacy/…/v0.2.1/apps/bot/package.json:17`) — библиотеке, тянувшей Bot API 7.x. Go-переписывание
взяло библиотеку на пять лет старше. Список потерь строился по возможностям бота и этого не увидел.

### Выбор замены

| Библиотека | Bot API | Зависимости | Заметки |
|---|---|---|---|
| **`github.com/go-telegram/bot`** 🟢 | **10.2** (14.07.2026) | нулевые | В официальном списке Telegram, 384 зависимых проекта, релиз 03.08.2026 |

## 3. 🟢 Что для шаринга уже готово на сервере — и это меняет цену

P3 выкачен. `api-go/internal/calendars/` — 17 файлов, из них 8 тестовых:
`access.go`, `crud.go`, `members.go`, `members_handlers.go`, `sharing.go`, `store.go`.

Живые роуты (`api-go/cmd/api/main.go:177–191`):

```
GET    /api/calendars                       POST   /api/calendars
PATCH  /api/calendars/{id}                  DELETE /api/calendars/{id}
GET    /api/calendars/{id}/members
POST   /api/calendars/{id}/invites          ← приглашение
POST   /api/calendars/{id}/invite-links     ← ссылка с токеном
POST   /api/calendars/{id}/invitation       ← принять / отклонить
DELETE /api/calendars/{id}/members/{userId}
POST   /api/calendars/invite-links/accept
```

🔴 **Ограничение, определяющее форму шаринга в боте:** `inviteRequest` — это
`{Email string, Role string}` (`members_handlers.go:13`). **Пригласить по Telegram-id нельзя** —
такого пути в API нет.

Отсюда два канала, и цены у них разные:

- **Ссылка** (`POST /api/calendars/{id}/invite-links` → токен) — работает **без единой правки
  API**. Бот делает ссылку, пользователь пересылает её кому угодно в Telegram.
- **Выбор контакта** (`request_users` → `user_id`) — требует **нового пути в API**: найти
  пользователя по `tg_id` и пригласить его. Красивее, дороже, и упирается в то, что у адресата
  Telegram должен быть уже привязан к NeuroBoost.

⚠ **Задачи наследуют шаринг бесплатно:** у задачи есть `calendar_id`
(`api-go/internal/tasks/types.go`), значит задача в общем календаре уже общая. Отдельный
механизм «поделиться задачей» строить не надо.

## 4. Mini App: самая дешёвая правка календаря, какую можно сделать

Претензия «календарь хуже, чем в прошлых версиях» относится к dev-боту (подтверждено Денисом).
Настоящих регрессий три, и все три про навигацию — таблица в §5.

Но есть ход дешевле, чем чинить сетку из кнопок: **`WebAppInfo` открывает существующий
`web/` внутри Telegram**. Календарь тогда — не 42 кнопки, а тот же календарь, что в браузере,
с перетаскиванием и неделей.

Чего это стоит на самом деле: Telegram отдаёт Mini App'у `initData`, подписанный тем же
секретом бота. `api-go/internal/auth/` уже проверяет подпись Telegram-логина —
механизм тот же, вход другой. То есть это **новый обработчик авторизации, а не новая система**.

## 6. 🔴 Что «готово» значит для бота

CI (`.github/workflows/ci.yml`, job `backend`) бота **собирает и тестирует, но не деплоит ни
одного инстанса**. Оба живут на nl-2 и обновляются руками:

- **dev:** `/opt/neuroboost-bot`, `neuroboost-dev-bot`, @NeuroBoost_dev_bot
- **прод:** `/opt/neuroboost-bot-prod`, `neuroboost-prod-bot`, @NeuroBoost_assistant_bot

Проверено сегодня: у dev в `src/internal/handlers/` есть `schedule.go`, `settings.go`,
`planning.go`; **у прода их нет** — там код от 17 июня.

Отсюда: **в каждом плане выкатка на nl-2 — нумерованная задача с командами, а не приписка
в конце**, и проверка — `ls` на сервере, а не зелёный тест.

## 7. 🔴 Найдено после выбора размаха: чеклисты — возможность Telegram **Business**, а не обычного бота

`SendChecklistParams` (библиотека `go-telegram/bot@v1.23.0`, `methods_params.go`) первым полем
несёт `BusinessConnectionID`. Три независимых источника описывают метод одинаково:

- поиск по документации: *«send a checklist on behalf of a connected business account»*
- python-telegram-bot, обзорная таблица методов: *«Used for sending a checklist on behalf of
  the business account»* (и то же для `edit_message_checklist`)
- сам параметр стоит первым в структуре, как у прочих business-методов

⚠ **Чего я НЕ проверил и не выдаю за проверенное:** таблицу параметров на `core.telegram.org`
прочитать не удалось — страница обрезается при выборке, и мирроры машиночитаемой схемы стоят
на Bot API 8.3, где чеклистов ещё нет. То есть «`business_connection_id` обязателен» — вывод
из трёх описаний, а не строка из таблицы. Проверяется одним живым вызовом после миграции.

**Что это значит по существу.** Чеклист рисуется не ботом в переписке, а **аккаунтом**, к
которому бот подключён через Telegram Business. Telegram Business требует **Premium** у
владельца аккаунта. Значит «список строкой → нативный чеклист» работает у того, кто включил
Business и подключил бота, и не работает у остальных.

🟢 **Остальные три возможности этим не задеты — проверено в тех же моделях библиотеки:**

| Тип | Файл в библиотеке | Business нужен |
|---|---|---|
| `KeyboardButtonRequestUsers` (выбор контакта) | `models/reply_markup.go:82` | 🟢 нет |
| `UsersShared` / `SharedUser` (входящий ответ) | `models/forum.go:49,58` | 🟢 нет |
| `WebAppInfo` (Mini App) | `models/web_app.go:10` | 🟢 нет |

То есть **срез шаринга целиком выживает**, и Mini App тоже. Под вопросом только чеклисты.
