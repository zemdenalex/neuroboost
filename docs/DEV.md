# Dev-среда NeuroBoost — что где живёт и как это проверять

> Одна страница на вопрос «я хочу потрогать свежий код — куда идти». Всё ниже проверено
> чтением `.github/workflows/ci.yml` и `docker-compose*.yml` 18.09.2026, а не по памяти.

## Четыре адреса

| Что | Dev | Прод |
|---|---|---|
| Веб | https://dev.neuroboost.website | https://neuroboost.website |
| API | `https://dev.neuroboost.website/api` (на хосте `127.0.0.1:8081`) | `…/api` (`:8080`) |

Веб и API живут на одной машине (`/root/neuroboost-dev` и `/root/neuroboost`).
🔴 **Оба бота живут на ДРУГОЙ машине** — nl-2, `185.214.10.107`, каталоги
`/opt/neuroboost-bot` (dev) и `/opt/neuroboost-bot-prod`. Telegram с основного хоста недоступен.

## Что выкатывается само, а что руками

| Компонент | Dev | Прод |
|---|---|---|
| API | 🟢 авто, push в `develop` | 🟢 авто, push в `main` |
| Веб | 🟢 авто | 🟢 авто |
| Миграции | 🟢 сами на старте API | 🟢 сами |
| **Бот** | 🔴 **руками** | 🔴 **руками** |

🔴 **Бота не выкатывает ничто.** CI его собирает и тестирует (job `backend`, шаг «Build and
test bot») и на этом останавливается. Значит фраза «фича бота готова» ничего не говорит о том,
что её можно нажать. Прежде чем сказать «выкачено» — `ls` его `src/` на nl-2.

Выкат бота (обе среды одинаково, ключ `~/.ssh/ufo_servers`, `root@185.214.10.107`):

```bash
cd /opt/neuroboost-bot            # или -prod
mv src src.bak-$(date +%F)
# с рабочей машины:
git archive --prefix=src/ develop:bot | ssh -i ~/.ssh/ufo_servers root@185.214.10.107 \
  'cd /opt/neuroboost-bot && tar x'
# обратно на сервере:
docker compose up -d --build bot
```

🔴 `docker compose restart` **не перечитывает `.env`** — только `up -d --force-recreate`.
🔴 Логи бота печатают его токен. Читать только через фильтр:
`docker logs neuroboost-dev-bot 2>&1 | sed -E 's/bot[0-9]+:[A-Za-z0-9_-]+/bot<REDACTED>/g'`

## 🔴 Push в `develop` стирает dev-базу

`ci.yml:308–312`: перед сборкой dev-деплой делает `pg_dump -c --if-exists` **прода** и
заливает его в dev-базу. То есть:

- всё, что ты натыкал на dev, **исчезает при следующем push'е в `develop`**;
- dev-база — **своя**, не копия прода: копирование в CI не работало никогда и убрано 23.09 (`docs/tasks-prohod3-2026-09-23.md`, P6). Что создал на dev — остаётся между деплоями;
- если тест зависит от заведённых данных — заводить их **после** деплоя, не до.

⚠ Отсюда же правило, о котором Денис просил отдельно: **не пушить `develop`, пока он проходит
staging руками** — push не просто пересобирает стенд, он ещё и стирает данные под ним.

## Как проверить, что выкатилось именно то

Версия в `/api/health` захардкожена (`internal/status/handlers.go` → `"0.4.0"`) и ничего не
доказывает. Что доказывает:

```bash
# API: какой коммит собран
ssh root@<host> 'cd /root/neuroboost-dev && git rev-parse --short HEAD'
# бот: какой код лежит рядом с контейнером
ssh -i ~/.ssh/ufo_servers root@185.214.10.107 'ls -la /opt/neuroboost-bot/src/internal/handlers | head'
# в самом боте: Настройки → «Что нового» печатает версию и где она (dev/прод)
```

Последнее — самый дешёвый способ: экран «Что нового» берёт текст из
`bot/internal/release/notes.go`, и у каждой версии там написано, **где она на самом деле**
(«на dev, в проде ещё нет»). Строка версии живёт в исходниках бота намеренно: бот на nl-2
работает из скопированной папки без репозитория рядом, и файл, который надо помнить отдельно,
будет забыт.

## Локальный запуск

```bash
docker compose up -d                      # api + db + web
cd api-go && go build ./... && go vet ./... && go test ./...
cd bot    && go build ./... && go vet ./... && go test ./...   # ДРУГОЙ модуль, отдельная команда
cd web && pnpm typecheck && pnpm test --run && pnpm build
cd web && pnpm dev                        # ровно порт 5173, ровно localhost (CORS whitelist)
```

⚠ Фронт запускать только из реального пути `C:\E_Drive\…`, не из `E:\…` — junction ломает
резолв `main.tsx`.

⚠ Тесты API, которым нужна база, **молча скипаются без `DATABASE_URL`**. Зелёный прогон без
этой переменной не означает, что SQL проверен.

## Сервисные вызовы к API

Эндпоинты `/api/svc/*` (их зовёт бот) авторизуются заголовком **`X-Service-Token`**, а не
`Authorization: Bearer`. С неправильным заголовком приходит 401 с пустым `data` — и это
выглядит ровно как «нечего отдавать». Смотреть код ответа, а не тело.

Токен — в `~/.claude/projects/<project>/memory/service-token-staging.txt`, не в репозитории.

## Что ломается чаще всего

| Симптом | Обычная причина |
|---|---|
| Бот отвечает старым текстом | его не выкатили — CI этого не делает |
| Данные на dev пропали | push в `develop` перезалил базу из прода |
| Переменная окружения «не применилась» | `restart` вместо `up -d --force-recreate` |
| Пустой ответ API | не тот заголовок / протухший токен / не тот метод — смотреть статус |
| «Тесты зелёные», а на стенде не работает | тесты БД скипнулись без `DATABASE_URL` |
