# API v0.4.11.4 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Повторяющиеся задачи с состоянием по дням, превращение задачи в событие и обратно, настраиваемая частота напоминаний, и четыре мелких долга — всё, что требует `api-go`.

**Architecture:** Новый **leaf-пакет `internal/recurrence`** (разбор RRULE и раскрытие вхождений) — им пользуются `events`, `tasks` и `reminders`, а он не зависит ни от кого. Повтор задачи живёт в `task.rrule` плюс **разреженная** `task_occurrence` — одна строка на день, с которым что-то произошло, как `event_exception` для событий. Долбёжка не создаёт строк напоминаний вперёд, а **переносит** существующую.

**Tech Stack:** Go 1.22, chi, pgx/v5, PostgreSQL 16, golang-migrate (следующая миграция — **000017**), React 18 + TS во `web/`, отдельный модуль `bot/`.

**Spec:** `docs/superpowers/specs/2026-09-18-api-v04114-recurring-tasks-design.md`
**Очередь релизов:** `docs/plan-relizov-v04113-v04115.md`

`Occurs` — календарными днями, без времени:

```go
// Occurs reports whether `day` belongs to the series anchored at `anchor`.
//
// 🔴 Both are truncated to a calendar DAY in the caller's location before
// comparison. A task has no clock: «выпить таблетки 19 сентября» is a day, and
// comparing instants would make an occurrence appear or vanish depending on the
// hour the question is asked.
func Occurs(r Rule, anchor, day time.Time) bool {
	a := dayOf(anchor)
	d := dayOf(day)
	if d.Before(a) {
		return false
	}
	n, ok := stepsBetween(r, a, d)
	if !ok {
		return false
	}
	if r.Count != nil && n >= *r.Count {
		return false
	}
	if r.Until != nil && d.After(dayOf(*r.Until)) {
		return false
	}
	return true
}
```

`stepsBetween` возвращает номер вхождения и `false`, если день не попадает в шаг: для `DAILY` — `diffDays % interval == 0`; для `WEEKLY` — тот же остаток по 7·interval и совпадение дня недели; для `MONTHLY` — совпадение числа месяца и `diffMonths % interval == 0`.

⚠ 31-е число в коротком месяце: вхождения нет (не переносить на 30-е). Это то же, что делает сегодняшний генератор событий — проверить `events/recurrence.go:82` и **повторить его поведение**, а не выбрать своё.

```sql
-- 000017_recurring_tasks.up.sql
-- Повторяющиеся задачи и связь задачи с событием.

ALTER TABLE task ADD COLUMN IF NOT EXISTS rrule         TEXT;
ALTER TABLE task ADD COLUMN IF NOT EXISTS repeat_anchor DATE;
ALTER TABLE task ADD COLUMN IF NOT EXISTS nag_minutes   INTEGER;
-- 🔴 ON DELETE SET NULL, not CASCADE: deleting the event created from a task
-- must not delete the task. The task is the thing the person wrote down.
ALTER TABLE task ADD COLUMN IF NOT EXISTS event_id UUID REFERENCES event(id) ON DELETE SET NULL;

ALTER TABLE event ADD COLUMN IF NOT EXISTS nag_minutes INTEGER;

-- Sparse by design: a row exists only for a day something happened to. A year
-- of daily pills is as many rows as times a button was pressed, not 365.
CREATE TABLE IF NOT EXISTS task_occurrence (
    id         UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id    UUID NOT NULL REFERENCES "user"(id) ON DELETE CASCADE,
    task_id    UUID NOT NULL REFERENCES task(id)  ON DELETE CASCADE,
    occurrence DATE NOT NULL,
    state      TEXT NOT NULL CHECK (state IN ('done', 'skipped')),
    acted_at   TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE (task_id, occurrence)
);
CREATE INDEX IF NOT EXISTS idx_task_occurrence_task ON task_occurrence(task_id, occurrence);
CREATE INDEX IF NOT EXISTS idx_task_rrule ON task(calendar_id) WHERE rrule IS NOT NULL;
```
