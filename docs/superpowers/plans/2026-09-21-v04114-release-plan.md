## Общие правила для всех кусков

- 🔴 **Каждый тест обязан мочь упасть** — саботаж компилируется, применяется и читается целиком.
  Проверять **ноль `FAIL`**, а не число `ok` (21.09: 8 ok из 9 пакетов, один упал молча, CI
  прода красный).
- 🔴 **Тест идёт через ту же дверь, что клиент** — не сеять колонку INSERT'ом
  (`learning-a-test-that-seeds-the-column-never-opened-the-door`).
- DB-тесты api-go: `DATABASE_URL` + `-count=1`, иначе скип или кэш
  (`memory/test-database.md`). Таблицы-зонды — `DROP TABLE IF EXISTS` **в начале** теста.
- Правка файлов — инструментами Edit/Write. Массовая замена скриптом 21.09 переписала 12 файлов
  в CRLF; поймал это только тест, читающий исходник с диска.
- Бот выкатывается **руками** на nl-2 (gotcha 19). «Готово» про бота — только после `ls src/`.
- Мерж в `main` = релиз прода, только по явному «да».

### A. Задача ↔ событие 🟢 форма выбрана

**Его форма, «1 + 3»** (`graph/log.md`, 20.09): спросить **перенести или связать** · показать,
**какое поле чем станет** · спросить **недостающее**.

**Что есть:** `POST /api/tasks/{id}/convert` с 18.09 (`api-go/internal/tasks/convert.go`),
режимы `move` / `link`, поля `starts_at`, `ends_at`, `all_day`, `calendar_id`. Связь —
`event.task_id` (`ON DELETE SET NULL`), вторая колонка снята миграцией 000018.

**Что сделать в боте:**
1. Кнопка на карточке задачи: **📅 В календарь**.
2. Экран выбора: **Перенести** (задача исчезает, остаётся событие) · **Связать** (оба живут,
   событие помнит задачу). Одной строкой под каждым — что произойдёт.
3. Экран соответствия полей, до подтверждения:
   `название → название` · `оценка → длительность` · `срок → день` · `описание → описание` ·
   `теги → теги` · `повтор → повтор` · ⚠ `приоритет → (у события нет)` — сказать честно.
4. Недостающее спросить кнопками: **время начала** (у задачи есть день, нет часа),
   **длительность**, если нет оценки. Календарь — по умолчанию тот же, что у задачи.
5. Подтверждение → `convert` → карточка события.

**Приёмка:** перенос убирает задачу из списка, событие появляется в дне календаря; связь
оставляет оба и событие открывает свою задачу; задача без срока спрашивает день.

🟡 **Спросить:** при «связать» — отметка события выполненным закрывает задачу, или они живут
независимо?

### B. Символ приоритета — выбор из трёх + онбординг 🟢

Денис 21.09: *«Я думаю 1-3 в настройках, и спрашивать на онбординге»*. Повод — Настя: *«смайлики
слишком из разных цветов, нет одного стиля»*.

**Варианты** (превью показаны ему 21.09):
1. 🔴🟠🟡🟢🔵 цветные кружки — **по умолчанию**, как сейчас
2. `● 1` / `○ 3` — точка одного цвета + цифра (заодно снимает gotcha 4: 1 = срочно)
3. `—` только тире, приоритет порядком строк

**Что сделать:** ключ `settings.bot.priority_style`; одна функция отрисовки со стилем;
экран в ⚙️ Настройки; шаг в онбординге после языка и зоны, **с превью всех трёх**.

**Приёмка + страховка:** скан-тест, что ни один обработчик не зовёт `format.PriorityEmoji`
мимо стилевой функции — иначе один экран останется в старом стиле и никто не заметит.

### C. Отписка от обновлений

Денис 21.09: *«в будущем надо будет сделать кнопку отписаться от обновлений»*.

- ключ `settings.bot.updates` (по умолчанию — подписан);
- кнопка **🔕 Не присылать обновления** под каждой рассылкой и в ⚙️ Настройки;
- рассылка становится функцией, а не разовым скриптом, и **пишет результат по получателю**
  (по хэшу id): 21.09 скрипт отдал сводку `200/403/сеть`, и понять, кому повторить, было
  нельзя без вопроса Денису.
