## Phase 1: Calendar UX Fix

**Goal:** Make the calendar feel responsive and correct. This is the core feature — everything else builds on it.

### 1.1 Fix Event Interaction Model

**Current bug:** `DayColumn.tsx:107` — clicking the center of an event calls `onDragStart` with `'resize-end'` instead of `'move'`. This means single-clicking an event immediately triggers resize behavior instead of selecting it. Also `DayColumn.tsx:104` — both top and bottom resize handles pass `'resize-start'`, with no distinction between which end.

**Target interaction model:**

| Action | Behavior |
|--------|----------|
| Single click on event body | Select event (highlight, show selected state). No drag/resize. |
| Double click on event body | Open EventEditor modal for editing |
| Click + drag on event body | Move event to new time/day |
| Click + drag on top handle (8px zone) | Resize start time |
| Click + drag on bottom handle (8px zone) | Resize end time |
| Click + drag on empty grid | Create new event (ghost preview) |
| Escape key | Deselect event / cancel drag |
| Arrow keys (when event selected) | Navigate between events |
| Shift+Arrow (when event selected) | Move event by 15min/1day |

**Implementation:**

**File: `DayColumn.tsx` (lines 64-110)**
- Separate `onMouseDown` from `onDragStart`. On mousedown, record the click target and position but DON'T start any drag yet.
- Use a threshold (5px movement) before entering drag mode. If mouse releases without exceeding threshold, treat as click (select) or double-click (edit).
- Fix line 104: check `isTopHandle` vs `isBottomHandle` and pass `'resize-start'` or `'resize-end'` respectively.
- Fix line 107: change `'resize-end'` to `'move'` for body drag.

**File: `useWeekGridDrag.ts`**
- Add a `dragThreshold` state. Track mousedown position. Only transition from "pending" to "dragging" after 5px of movement.
- Add `'move'` action type distinct from resize.
- Clean up `colTop` reset (line 66-94) — currently never resets on cancel.

**File: `EventBlock.tsx`**
- Add visual selected state (border highlight, subtle glow).
- Ensure resize handles show `cursor-ns-resize` only on hover, not on the entire event.

### 1.2 Fix Drag-to-Move Events

**Current state:** Move doesn't work because the body drag is routed to `'resize-end'` handler.

**Fix:** After correcting `DayColumn.tsx:107` to pass `'move'`, implement move handling in `dragHandlers.ts`:
- On move completion, call `onMoveOrResize({ id, startTime, endTime, action: 'move' })`.
- Preserve event duration — only shift start/end by the delta.
- Allow cross-day moves (calculate target day from mouse X position).
- Show ghost preview during move (reuse existing GhostPreview with "move" styling).

### 1.3 Fix Multi-Day Event Resize

**Current bug:** Resizing a multi-day event collapses it to 1 day. The bottom handle creates a new event from the end of the original instead of extending.

**Root cause:** `EventBlock.tsx:69-75` — resize handles only render for single-day events. Multi-day segments don't get handles.

**Fix:**
- For multi-day event segments: render bottom handle on the LAST segment only, top handle on the FIRST segment only.
- On resize completion, update the event's `end_time` (bottom) or `start_time` (top) — don't create a new event.
- Validate that `end_time > start_time` after resize.

### 1.4 Fix Task-to-Calendar Drag

**Current bugs:**
1. Dragging a task from sidebar DELETES the task
2. Created event is a plain event, not linked to the task

**Root cause:** The calendar page calls `scheduleTask()` API which sets task status to SCHEDULED and creates an event, but the frontend then reloads tasks — the SCHEDULED task disappears from the sidebar because the filter excludes it.

**Fix:**
- Backend `ScheduleHandler` (`api-go/internal/tasks/handlers.go`): ensure the created event includes `task_id` reference. Keep task visible with SCHEDULED status.
- Frontend: after scheduling, reload both events AND tasks. Show SCHEDULED tasks in sidebar with a visual indicator (calendar icon, dimmed).
- `useDragTask.ts`: set `effectAllowed: 'copy'` instead of `'move'` (line 10) — visual signal that the task isn't deleted.

### 1.5 Fix Task Sidebar

**Bug 1:** Sidebar opens by default on page load.
- Fix: Initialize sidebar as collapsed. Store open/closed state in localStorage.

**Bug 2:** Adding a task uses browser `prompt()` instead of editor modal.
- The `onCreateTask` callback in `TaskSidebar.tsx:99` delegates to the parent. Check `Calendar.tsx` for the implementation — likely uses `window.prompt()`.
- Fix: replace with inline task creation form or open the TaskEditor modal.

### 1.6 Performance Optimization

**Bug:** Creating events takes ~5s with >20 events visible.

**Root cause candidates:**
- Re-rendering all events on every state change (no memoization).
- `toNbEvent()` conversion running on every render for all events.
- Drag calculations iterating all events.

**Fix:**
- Memoize `EventBlock` with `React.memo` and stable keys.
- Memoize event position calculations in `weekgrid.utils.ts`.
- Debounce drag preview updates (currently fires on every mousemove).
- Profile with React DevTools to identify the actual bottleneck before optimizing further.

### 1.7 Fix Language Bugs

**Bug L1:** Calendar day names stay Russian when switching to English.
- **Root cause:** Day names in `WeekHeader.tsx` or `DayColumn.tsx` likely use `toLocaleDateString()` with hardcoded `'ru-RU'` locale or no locale parameter (defaults to system locale).
- **Fix:** Use `i18n.language` to determine locale for `toLocaleDateString()`, or use i18n keys for day names (e.g., `t('calendar.Mon')`, `t('calendar.Tue')`).

**Bug L2:** Task sidebar in calendar doesn't translate to Russian.
- **Root cause:** The exploration found all i18n keys are present in both locales. The issue is likely that `TaskSidebar.tsx` doesn't use `useTranslation()` or uses hardcoded English strings.
- **Fix:** Add `useTranslation('tasks')` to TaskSidebar and replace hardcoded strings.

## Phase 2: Mobile Polish

**Goal:** Make the app fully usable on phones (375px). This unlocks Telegram MiniApp.

### 2.1 Mobile Calendar Views

**Current state:** Shows 1 day, no way to switch days, no drag-create, cuts off at ~4pm.

**Implement 4 switchable mobile calendar views:**

| View | Description |
|------|-------------|
| **Day view** | Single day, swipe left/right to navigate. Tap to create. Drag-create supported. |
| **3-Day view** | 3 columns, horizontal scroll for more days. Drag-create supported. |
| **Mini-month + Day** | Compact month calendar on top, day view below. Tap a date to jump. |
| **Agenda view** | Chronological list of events. No grid, no drag. Simple and readable. |

**Switching:** Add a view selector in the calendar header (icon buttons or dropdown). Store preference in user settings (add `mobile_calendar_view` to settings schema).

**Implementation:**
- New file: `web/src/components/Calendar/MobileCalendar/MobileCalendarView.tsx` — view switcher
- New file: `web/src/components/Calendar/MobileCalendar/SwipeableDayView.tsx` — day view with touch swipe (use `touchstart`/`touchmove`/`touchend`)
- New file: `web/src/components/Calendar/MobileCalendar/ThreeDayView.tsx` — compact 3-column
- New file: `web/src/components/Calendar/MobileCalendar/MiniMonthView.tsx` — month picker + day
- New file: `web/src/components/Calendar/MobileCalendar/AgendaView.tsx` — list view
- Modify `Calendar.tsx` to render `MobileCalendarView` below `md:` breakpoint

**Full-day scroll fix:** The calendar cuts off at ~4pm because the grid container height is insufficient or the scroll area is constrained. Ensure the hour grid renders 0:00–23:59 (24 hours * `HOUR_PX` = 24 * 44 = 1056px) and the container allows full scrolling.

**Drag-create on mobile:** Use `touchstart`/`touchmove`/`touchend` with a long-press threshold (300ms hold before drag begins). Show ghost preview on drag. Not available in Agenda view.

### 2.2 Fix Event Editor Mobile Overflow

**Current bug:** `EventEditor.tsx:27` — `max-w-md` (448px) is wider than 375px phones. `p-6` (48px total padding) leaves only ~300px for content.

**Fix:**
```
className="bg-zinc-900 border border-zinc-700 rounded-lg p-4 sm:p-6 w-[95vw] max-w-md max-h-[85vh] overflow-y-auto"
```
- `w-[95vw]` constrains to screen width on mobile
- `p-4 sm:p-6` reduces padding on small screens
- `max-h-[85vh]` (reduced from 90vh) leaves room for mobile browser chrome
- Add `pb-20` at bottom of form content to ensure save button isn't hidden by mobile keyboard

### 2.3 Fix Hamburger Icon Overlap

**Current bug:** Hamburger icon renders on top of the NeuroBoost logo.

**Root cause:** `HamburgerDrawer.tsx` renders the hamburger button with absolute positioning that doesn't account for the logo space.

**Fix:** In the header component, add a conditional left section: when hamburger nav is active, render the hamburger button BEFORE the logo with proper flex spacing (`flex items-center gap-3`). Remove absolute positioning from the hamburger button.

### 2.4 Fix FAB / Feedback Button Overlap

**Current bug:** FAB and feedback button both position at bottom-right, overlapping.

**Fix:**
- When FAB nav is active, move feedback button to bottom-LEFT (`left-4` instead of `right-4`).
- Or: stack vertically — FAB at `bottom-20`, feedback at `bottom-4`.
- Add a check in `FeedbackButton.tsx`: read mobile nav type from settings, adjust position accordingly.

### 2.5 Mobile Nav Type Actually Applied

**Current state:** Settings saves the mobile nav type but `Layout.tsx` doesn't read it — all three components may render regardless.

**Fix:** In `Layout.tsx`, read `mobile_nav` from user settings (or localStorage fallback). Conditionally render only the active mobile nav component:
```typescript
{mobileNav === 'bottom_tabs' && <BottomTabBar />}
{mobileNav === 'hamburger' && <HamburgerDrawer />}
{mobileNav === 'fab' && <FabBottomSheet />}
```

## Phase 3: Telegram Bot + MiniApp

**Goal:** Full assistant bot with commands + embed the web app as a Telegram MiniApp.

### 3.1 Tech Stack

| Component | Stack |
|-----------|-------|
| Bot framework | Python 3.12, aiogram 3 |
| Web framework | FastAPI (for webhook) |
| Database | Same PostgreSQL (shared with Go API) |
| MiniApp | Existing React app with Telegram WebApp JS SDK |
| Deployment | Docker container alongside existing services |

### 3.2 Assistant Bot Commands

**Bot: @NeuroBoost_assistant_bot**

| Command | Description | Response |
|---------|-------------|----------|
| `/start` | Welcome + persistent keyboard | Welcome message, set up reply keyboard |
| `/help` | List all commands | Formatted command list |
| `/today` | Today's schedule | Chronological list of today's events |
| `/week` | Week overview | Summary: N events, N tasks due, busiest day |
| `/tasks` | Task list by priority | Grouped by priority (Emergency → Buffer) |
| `/newtask` | Create task wizard | Step-by-step: title → priority → deadline → energy → confirm |
| `/note` | Quick capture | Save text as task with INBOX status, priority 5 |
| `/settings` | User settings | Timezone, notification preferences |
| `/feedback` | Report bug/suggestion | Type selection → description → saved to feedback table |

**Persistent reply keyboard:** `Today | Tasks | + Note | Settings`

**Inline keyboards:** Task actions (Complete, Schedule, Edit, Delete) attached to each task in `/tasks` response.

**MiniApp button:** Add WebApp button to bot that opens `https://neuroboost.website` with Telegram auth context.

### 3.3 Notification Bot

**Bot: @NeuroBoost_notifications_bot**

| Notification | Trigger | Default |
|-------------|---------|---------|
| Event reminder | 30/10/5 min before event | 10 min |
| Daily planning nudge | Fixed time | 21:00 MSK |
| Weekly planning nudge | Fixed day+time | Sunday 18:00 MSK |
| Task deadline alert | Day before deadline | 09:00 MSK |
| Feedback alert (admin) | New feedback submitted | Immediate |

**Quiet hours:** 22:00–08:00 (configurable in /settings). Notifications queue and deliver after quiet hours end.

**Rate limiting:** Max 1 message per minute per user to avoid spam feel.

### 3.4 MiniApp Integration

- Use Telegram WebApp JS SDK (`telegram-web-app.js` from `https://telegram.org/js/telegram-web-app.js`)
- On MiniApp open: extract `initData` from Telegram, send to backend for auth
- Backend: new endpoint `POST /api/auth/telegram-webapp` — validates `initData` hash, returns JWT
- Frontend: detect Telegram context (`window.Telegram?.WebApp`), auto-login, hide redundant UI (header logo, login button)
- Set `MainButton` for primary actions (Save Event, Create Task)
- Use `BackButton` for navigation back

### 3.5 Project Structure

```

  assistant/
    __init__.py
    handlers.py      # Command handlers
    keyboards.py     # Reply + inline keyboards
    formatters.py    # Message formatting (HTML)
  notifications/

    handlers.py      # Notification delivery
  common/
    db.py            # Async PostgreSQL (asyncpg)

```

## Phase 5: Settings & Stubs Cleanup

**Goal:** Make all settings functional and clean up remaining issues.

### 5.1 UI Scale Applied Globally

**Current bug:** `Settings.tsx:105-110` — `useEffect` sets `document.documentElement.style.fontSize` but the cleanup function resets to 100% when leaving Settings. This means the scale only persists while on the Settings page.

**Fix:** Move UI scale application to `App.tsx` or a global hook `useUIScale()`:
- Read `ui_scale` from user settings on mount
- Apply to `document.documentElement.style.fontSize`
- No cleanup (persist across all pages)
- Settings page controls the value, global hook applies it

### 5.2 Feature Toggles Working

**Current state:** Toggles save to DB but don't affect the UI.

**Fix:** Create a `useFeatureFlags()` hook that reads `user.settings.features`:
- In `router.tsx`: conditionally render routes based on feature flags
- In navigation components: hide/show nav items based on flags
- Features that can be toggled: Dreams, Goals, Projects, Opportunities, Needs, Graph, Timeline, Tools

### 5.3 Export/Import

**Export:** Download user data as JSON:
```json
{
  "version": "0.4.1",
  "exported_at": "2026-04-15T12:00:00Z",
  "events": [...],

  "reflections": [...],
```

**Import:** Upload JSON, validate schema, upsert records.

**API:**
- `GET /api/export` — returns full user data as JSON

### 5.4 Remaining Small Bugs

- Task sidebar default state: closed (localStorage)
- Task creation from sidebar: use modal editor, not `prompt()`

## Decisions & Trade-offs

| Decision | Rationale |
|----------|-----------|
| Python for Telegram bot (not Go) | Aiogram 3 is proven in user's stack, faster bot development. Go API stays for HTTP. |
| 4 mobile calendar views | User wants all options. Setting-based switching keeps the code modular. |
| Pomodoro as frontend-only | No backend needed for timer. Session data too granular for DB. |
| Kanban reuses Tasks API | No new backend — just a different frontend view of existing data. |
| Shared PostgreSQL for bot | Simpler than API-to-API calls for read operations. Writes go through Go API. |
