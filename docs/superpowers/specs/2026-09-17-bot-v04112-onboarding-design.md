## A. Онбординг

### Когда показывается

- Флаг `bot.onboarded = true` в blob'е настроек, **не** в памяти бота: бот перевыкатывается
  руками, и флаг в `UserState` означал бы онбординг заново после каждого деплоя.
  Запись — read-merge-write, как `SetBotLang` (gotcha 21).
- Запускается на **первое сообщение** пользователя без флага — `/start`, текст или кнопку меню.
  Настя и Муфид уже нажимали `/start`, поэтому ждать только `/start` значило бы не показать
  его тем, ради кого он делается.
- 🔴 **Inline-колбэки онбординг НЕ запускают.** Кнопки под уведомлением («Отложить»,
  «Готово») и под старыми сообщениями работают как раньше: человек, отвечающий на
  напоминание, не должен попасть в анкету.
- Прочитать флаг не удалось → онбординг **не** показывается (лучше пропустить один раз, чем
  показывать каждому при сбое API). Записать не удалось → покажется снова в следующий раз.

### Шаги

**1. Язык.** Заголовок двуязычный — язык ещё неизвестен.

```
🧠 NeuroBoost

Выбери язык · Choose language
[✅ Русский] [English]
[Дальше · Next →]
```

Предвыбор: сохранённый `bot.lang`, если есть; иначе `from.language_code` из Telegram —
`ru*` → русский, **всё остальное → английский**. ⚠ Арабский у Муфида даст английский: это
делает выбор видимым с первого экрана, но языка не добавляет. Нажатие языка сразу
перерисовывает экран на нём.

**2. Часовой пояс — через часы, а не через название зоны.**

```
🕐 Сколько у тебя сейчас времени?

[✅ 17:40 — Москва]
[15:40] [16:40] [18:40] [19:40]
[20:40] [21:40] [22:40] [Другое…]
```

Человек знает, который час, и не обязан знать, что он `Asia/Yekaterinburg`. Первая кнопка —
текущая зона аккаунта (`/api/auth/me` → `timezone`). Остальные — смещения от неё, пишутся как
`Etc/GMT±N`. «Другое…» принимает текстом IANA-имя или `UTC+5`.
Запись — `PATCH /api/auth/me {"timezone": …}`: это **отдельная колонка**, blob `settings` она
не трогает (проверено чтением `auth/handlers.go:238–247`, в тесте подтверждается).

⚠ `Etc/GMT` не знает летнего времени. Для России это верно; для Европы кнопка «Другое…».

**3. Попробуй.**

```
✍️ Напиши, что запланировать, одной строкой — как в заметках:

   Ужин завтра 19:00

Я покажу, что понял, и создам только после «Создать».
[Пропустить]
```

Дальше — **обычный** поток создания с обычной карточкой, без отдельной «учебной» версии: учить
нужно тому, что будет потом. После «Создать» или «Отмена» — шаг 4.

**4. Готово.**

```
Готово ✅

📅 Создать — событие или задача, можно списком
🗓 Календарь — что уже запланировано
⚙️ Настройки — язык, свои слова, рабочие часы

Меню внизу ↓
```

Флаг пишется здесь.

### Выход

- **«Пропустить»** есть на каждом шаге и пишет флаг.
- 🔴 **Кнопка меню посреди онбординга = пропустить**: флаг пишется, экран открывается. Это
  тот же принцип, что починка 15.09 (кнопка меню сильнее любого потока) — человек не должен
  застревать в анкете.
- Повторить — `⚙️ Настройки → ❓ Как пользоваться`.

## B. Гайд «Новое событие»

Сейчас — 20 строк. Станет:

```
📅 Новое событие

Напиши одной строкой, например:
  Ужин завтра 19:00
  зарядка каждый день 07:00

Можно несколько строк сразу — списком.
[📖 Все слова и примеры]
```

Кнопка разворачивает нынешний полный текст правкой того же сообщения. Ничего не удаляется.
То же для гайда задач.

## C. «Планирование»

Кнопка убирается из меню. **Обработчик и колбэк `planning` остаются**: старые сообщения с этой
кнопкой не должны превращаться в «не понял». Вернётся вместе с функцией свободных слотов.

## D. 🔴 Дни в списке идут по порядку

**Воспроизведение (переписка 16.09, среда):**

```
monday / 10 wake up …   → пн 21.09
tuesday / 12:40-13:30   → вт 22.09
friday / 13:30 -15 exam → пт 18.09   ← раньше понедельника
```

Каждая строка по отдельности верна по правилу Дениса («без приставки — ближайший, включая
сегодня»). Правило не договорено для **блока**: человек, пишущий неделю сверху вниз, имеет в
виду дни по порядку.

**Расширение правила:** в списке день недели из заголовка не может быть раньше дня предыдущего
заголовка — иначе +7. Не трогается: явная дата (`16.09`), относительная (`завтра`), приставка
(`следующая пятница`). Первый заголовок — как раньше.

Тест пишется первым, из настоящей переписки, и показывается красным.

## E. Свой период повтора

API уже принимает `INTERVAL`, `COUNT`, `UNTIL` — работа только в боте.

| Ввод | RRULE |
|---|---|
| `раз в 3 дня` · `каждые 3 дня` · `every 3 days` | `FREQ=DAILY;INTERVAL=3` |
| `раз в 3 недели` · `every 3 weeks` | `FREQ=WEEKLY;INTERVAL=3` |
| `… 10 раз` · `10 times` | `;COUNT=10` |
| `… до 01.12` · `until 01.12` | `;UNTIL=…` |

- 🔴 `N раз` и `до <даты>` читаются **только при наличии повтора в строке**: «отжаться 12 раз»
  остаётся названием, «до 01.12» без повтора — не конец серии.
- Выбор частоты кнопками получает **«✏️ Своя частота»** → текстом.
- «Изменить» получает поле **«Конец повтора»**: никогда · N раз · до даты. Отдельным вопросом
  при создании **не** спрашивается — «lots of steps» ровно про это.
- Карточка: `🔁 раз в 3 дня · 10 раз`.

## F. Событие на несколько дней

| Ввод | Результат |
|---|---|
| `отпуск с 14.09 по 29.09` · `14.09-29.09` · `from 14.09 to 29.09` | одно событие «весь день» 14.09–29.09 |
| `с понедельника по среду` | весь день, пн–ср |
| `конференция с 14.09 10:00 по 16.09 18:00` | одно событие со временем через дни |

- Карточка: `🗓 14.09 – 29.09 · 16 дней`.
- Конец раньше начала → строка с `⚠ проверь`, а не молчаливая перестановка.
- ⚠ **Проверить до кода:** как API хранит конец многодневного all-day (включительно или
  исключительно) — веб его уже рисует, образец в `web/e2e/multiday-resize.spec.ts`.
- `с … по` конфликтует с `до` из повтора: `до` — только при повторе (см. E), `по` — только
  диапазон дат.

## G. Напоминания галочками

```
🔔 Напоминания
[✅ За 10 минут] [   За 30 минут]
[✅ За час     ] [   За день    ]
[✏️ Своё время] [🚫 Не напоминать]
[Готово]
```

- Галочки переключаются правкой того же сообщения. «Не напоминать» снимает все. Пресет из
  настроек — отмеченным по умолчанию.
- «Своё время» → текстом: `2ч`, `45м`, `3д`, `за 2 часа` — тот же разбор, что
  `RecogniseReminderOffset`. Добавленное появляется отдельной отмеченной кнопкой.

## H. Карточка у списка задач

Список задач перестаёт создаваться сразу — показывает карточку, как список событий:
нумерованные строки (приоритет, оценка, срок, теги) и `✅ Создать все` · `✏️ Изменить №` ·
`❌ Отмена`. Правка одной задачи — те же поля, что у задачи сейчас, плюс «Убрать из списка».
