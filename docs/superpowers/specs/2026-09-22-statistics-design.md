## 1. Экран

```
📊 Неделя 21–27 сентября

      00    06    12    18
пн  ······▁▃▇▇▅▃▁▁▁▂······   5,5 ч
вт  ·······▂▅▅▅▅▂··▂▃▃····   7 ч
ср  ······················   —
…
Занято: 18,5 ч · В планах: 21 ч
✅ Закрыто задач: 6 · 📋 Открыто: 14 · 🔴 Просрочено: 2
🔁 Серии: 11 дней из 14
📝 Рефлексии: 4 из 7 дней

[ ← ] [Неделя] [Месяц] [ Год ] [ Всё ] [ → ]
[ Всё ] [События] [Задачи] [Рефлексии]
[📏 Шкала: 24 ч]          [« Меню]
```

- Активный период и сущность отмечены `✓`, как во всех экранах выбора бота.
- ← → листают **в обе стороны**: прошлое — что было, будущее — что уже запланировано. У «Всё»
  стрелок нет.
- Сетка — в `<pre>`, чтобы столбики стояли ровно; ширина строки ≤ 36 знаков (телефон).
- Справа от строки — занятые часы строки; пустая строка — `—`.

### Строки и столбики

| Период | Строка | Столбик | Столбцов |
|---|---|---|---|
| Неделя | день (пн…вс) | час | 24 (или окно шкалы, §3) |
| Месяц | неделя ISO, попавшая в месяц | день недели | 7 |
| Год | месяц | неделя месяца (по понедельникам) | 4–5 |
| Всё | год (с первого года данных) | месяц | 12 |

### Высота — заполненность временем

Символы: `·` (ничего) и `▁▂▃▄▅▆▇█` (восемь уровней). Значение ячейки = **занятое время в ячейке /
ёмкость ячейки**. Ёмкость = часов в ячейке по шкале (§3): час — 1 ч (при 24 ч) · день — 24 ч ·
неделя — 7 × 24 · месяц — дней × 24. Больше 100 % (возможно при шкале «рабочие часы») — `█`.

🔴 **Занятое = объединение интервалов**, а не сумма. Два события на одно время дают один час,
а не два — слова Дениса 20.09. «В планах» — сумма длительностей; разница между строками и есть
мера наложений. События на весь день в «Занято» **не входят** (весь день — не занятость часа),
считаются отдельной строкой, если есть.

## 2. Сущности (второй ряд)

| Кнопка | Столбики | Итоги |
|---|---|---|
| **Всё** | события (как «События») | все строки итогов |
| **События** | занятое время событий | Занято · В планах · Весь день · Повторяющихся |
| **Задачи** | время закрытых задач в день закрытия: записанное (`actual_minutes`), иначе оценка, иначе **30 мин**. День серии, отмеченный «сделано», считается так же | Закрыто · Открыто · Просрочено · Серии: сделано дней N из M |
| **Рефлексии** | неделя — `✓`/`·` по дням; дальше — доля дней с рефлексией | Написано: N из M дней |

⚠ «Будущее» для задач: закрытого там нет — показываются открытые со сроком в периоде, строкой
итога, без столбиков.

## 3. Шкала — что считать полным столбиком

Ключ `settings.bot.stats_scale`, запись через `MergeSettings` (gotcha 21):

| Значение | Полный столбик | Столбцы недели |
|---|---|---|
| `day24` — **по умолчанию** | 24 ч в сутках | 00…23 |
| `work` | рабочее окно из ⚙️ (по умолчанию 08–20) | часы окна |
| `peak` | самая заполненная ячейка экрана | 00…23 |

Где выбирается — **три места**, по словам Дениса:
1. кнопка **📏 Шкала** на экране статистики;
2. ⚙️ Настройки;
3. онбординг — шаг рядом с шагом символа приоритета (кусок B спеки 11.4), с тремя превью.

## 4. Месячный календарь

Точка «есть события» (`calendar.go`, `busy`) заменяется символом заполненности дня той же
функцией и той же шкалой. Один расчёт на оба экрана — иначе календарь и статистика однажды
покажут один день по-разному.

## 5. API — дни серий

**Новое, только чтение, без миграции:** `GET /api/tasks/occurrences?from=YYYY-MM-DD&to=YYYY-MM-DD`
→ `{"data": [{"task_id", "occurrence": "YYYY-MM-DD", "state": "done|skipped"}]}` по задачам из
календарей, которые пользователь **видит** (`CalendarIDsFor`). Диапазон ≤ 366 дней, иначе 400
`RANGE_TOO_LARGE` — «Всё» запрашивается по годам.

«Сколько дней серии было положено» (M в «N из M») бот считает сам: список задач уже отдаёт
`rrule` и `repeat_anchor` (`tasks/types.go:59`, проверено 22.09). День рефлексии — `created_at`
в зоне пользователя (`reflections/types.go:16`).

## 6. Откуда данные и сколько их

- Неделя/месяц/год: `GET /api/events` за период (серии приходят развёрнутыми), `GET /api/tasks`,
  `GET /api/reflections`, новая ручка §5.
- «Всё»: с года **первых данных** по текущий, запросом на каждый год. ⚠ Ежедневная серия за
  несколько лет — тысячи развёрнутых вхождений; если экран станет медленным, лечится
  агрегирующей ручкой в API, а не кэшем в боте. Сейчас не делается.
- Вся арифметика — **чистые функции** (как `BuildStats` сейчас): вход — события/задачи/отметки,
  период, шкала, зона пользователя; выход — сетка чисел. Отрисовка отдельно.

## 7. Приёмка

- [ ] Два события 10:00–11:00 и 10:30–11:30 → «Занято» 1,5 ч, «В планах» 2 ч
- [ ] Неделя: у дня с 12 ч занятого при шкале 24 ч — столбики `▅`-уровня в занятые часы; при `work` 08–20 — `█`
- [ ] ← три раза → неделя трёхнедельной давности; → из текущей — следующая неделя с запланированным
- [ ] Месяц / Год / Всё — строки и столбики как в таблице §1
- [ ] Задачи: закрытая с оценкой 90 мин → 1,5 ч в день закрытия; без оценки → 30 мин
- [ ] Серия «каждый день», отмечено 3 дня из 7 → «Серии: 3 из 7»
- [ ] Рефлексии: `✓` в дни с рефлексией
- [ ] 📏 Шкала меняет высоту сразу; выбор сохраняется; онбординг спрашивает у нового пользователя
- [ ] Месячный календарь: вместо точки — тот же символ заполненности, что в статистике за тот день
- [ ] 🔴 Пользователь не в Москве: день и час считаются в **его** зоне (тест с `America/New_York`)
- [ ] Скан-тест: `▪` больше нигде в боте нет

## 8. Порядок работы

S1 (API: ручка дней серий, якорь в списке) → S2 (чистый расчёт сетки + тесты) → S3 (экран, кнопки,
листание) → S4 (шкала: настройка, кнопка, онбординг) → S5 (месячный календарь). Перед каждым —
`superpowers:writing-plans`.
