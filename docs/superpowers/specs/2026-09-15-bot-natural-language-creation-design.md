# Бот: создание естественным языком — токены, ключевые слова, карточка подтверждения, списки

**Первоисточник:** `ref/feedback/bot-zamechaniya-denisa-2026-09-15.md` (его слова дословно)
**Решения по объёму и спорным местам:** приняты Денисом 15.09, таблица в §2.

## 1. Откуда взялась, и что уже доказано красным

Пять замечаний Дениса после прохода бота. Четыре из них (1, 2, 3, 4) — **одна
перестройка**, и это главный вывод разбора: «уточнить частоту повтора», «уточнить
дату», «выбрать пресет напоминаний» и «ключевые слова» — это не четыре новых вопроса,
а **поля одной карточки подтверждения**. Делать их по отдельности значит трижды
переписать одно и то же место.

🔴 **Дефект, пойманный до всякого проектирования.** Его собственный пример из пункта 5:

```
parse.Parse("10:00 завтрак", вт 15.09)
  → Title = "к"          (ожидалось "завтрак")
  → Start = 16.09        (ожидалось 15.09)
```

`event.go:66` ищет день недели **подстрокой**: `strings.Index(lower, "завтра")` находит
«завтра» внутри «завтрак», вырезает шесть букв из названия и переносит событие на сутки.
Тест показан красным 15.09 и будет в дереве постоянным.

⚠ Это не единичная опечатка, а **свойство подхода**. Пункт 1 добавляет дни недели на
двух языках плюс сокращения. Подстрочный поиск на них катастрофичен: `mon` внутри
`money`, `sat` внутри `satisfied`, `sun` внутри `sunny`, `вт` внутри `втроём`,
`ср` внутри `среда` (безобидно) и внутри `срочно` (нет). Поэтому §3 — не украшение.

## 2. Решения Дениса (15.09)

| Вопрос | Ответ |
|---|---|
| Объём релиза | **Все пять пунктов в v0.4.11.1** |
| «среда», когда сегодня среда | **Сегодня** |
| «следующая среда», когда сегодня среда | **+7** |
| Английские дни | **Полные имена + сокращения + русские сокращения** (`пн`, `вт`, `ср`) |
| Свои слова для тегов | **В настройках пользователя**, через `MergeSettings`, и **не писать при сбое чтения** |

⚠ Четвёртая строка — самая дорогая: она и делает §3 обязательным, а не желательным.

## 3. Что считается сделанным

1. `среда 14:00-15:00 оркестр повтор` создаёт событие **в ближайшую среду**, 14:00–15:00,
   с названием **«оркестр»** — слово «повтор» в названии не появляется — и бот
   **спрашивает частоту**, потому что она не названа.
2. `10:00 завтрак` создаёт «завтрак» **сегодня** в 10:00.
3. Нажатие любой кнопки меню во время создания **прекращает создание** и открывает
   нажатый экран. Название пункта меню не становится названием события.
4. Каждое создание проходит через **карточку подтверждения** с тремя кнопками.
5. «Изменить → Название» кладёт следующий текст в название **дословно**: ключевые слова
   в нём не действуют. «Изменить → Теги» делает тегом даже слово `полдень`.
6. Список из нескольких строк **спрашивает**, одна это запись или несколько.
7. Краткий гайд по созданию показывает примеры **и то, как бот их поймёт**.

# 4. Архитектура: токены с провенансом

## Почему не «ещё один `strings.Replace`»

Сегодня `Parse` работает так: найти подстроку → вырезать из текста → то, что осталось,
есть название. Каждый новый распознаватель добавляет ещё одно вырезание, и остатки
копятся в названии — ровно та жалоба, которую Денис и подал.

Требование «изменить → название, и ключевые слова больше не действуют» делает старую
форму **невыполнимой в принципе**: чтобы перестать учитывать слова, надо знать, какие
слова были учтены, а `Parse` этого не возвращает.

## Форма

`bot/internal/parse/token.go` — новый файл, чистые функции.

```go
// Field says which part of the draft consumed a token. FieldNone means the
// token was not recognised and therefore belongs to the title.
type Field uint8

const (
    FieldNone Field = iota
    FieldDay          // среда, завтра, 16.09, следующая среда
    FieldTime         // 14:00, 14:00-15:00, полдень, утром
    FieldRepeat       // повтор, еженедельно, каждый день
    FieldAllDay       // весь день
    FieldKind         // задача
    FieldColour       // синий, красный, …
    FieldCalendar     // календарь работа, работа (если это имя календаря)
    FieldTag          // #тег и свои слова
    FieldReminder     // напомнить, за 15м, имя пресета
)

// Token is one whitespace-delimited word of the input, kept verbatim.
//
// 🔴 Text is what the user typed and is what rebuilds the title. Norm is the
// lowercased, punctuation-stripped form and is the ONLY thing matched against.
// Keeping them apart is what makes «оркестр,» match nothing and still print
// with its comma.
type Token struct {
    Text  string
    Norm  string
    Field Field
}

func Tokenize(line string) []Token
func Title(tokens []Token) string   // join of Field == FieldNone, original spacing normalised
```

Токен — это **слово**, поэтому граница слова достаётся даром: `money` никогда не будет
токеном `mon`. Отдельный `\b` не нужен и был бы неверен — он ASCII-ориентирован.

## Распознаватели

Каждый распознаватель — чистая функция `func(toks []Token, now time.Time, vocab Vocab) bool`,
которая помечает поля и возвращает, сработала ли. Порядок фиксирован и осмыслен:

| # | Распознаватель | Что claim'ит | Почему здесь |
|---|---|---|---|
| 1 | `recogniseExplicitDate` | `16.09`, `16.09.2026` | Число однозначнее слова |
| 2 | `recogniseRelativeDay` | `сегодня`, `завтра`, `послезавтра` | |
| 3 | `recogniseWeekday` | `[следующая\|эта\|прошлая] среда\|wednesday\|wed\|ср` | Два токена, когда есть приставка |
| 4 | `recogniseTimeRange` | `14:00-15:00`, `14:00`, `14.00` | До «полдня»: цифры точнее слова |
| 5 | `recogniseTimeWord` | `полдень`, `утром`, `вечером`, `ночью` | Только если №4 не сработал |
| 6 | `recogniseAllDay` | `весь день`, `all day` | Отменяет время, если оно было |
| 7 | `recogniseRepeat` | `повтор`, `повторять`, `еженедельно`, `каждый вторник` | |
| 8 | `recogniseKind` | `задача` | |
| 9 | `recogniseColour` | `синий`, `синее`, `red`, … | |
| 10 | `recogniseCalendar` | `календарь <слово>`, либо слово = имя календаря | Требует `GET /api/calendars` |
| 11 | `recogniseReminder` | `напомнить`, `за 15м`, имя пресета | |
| 12 | `recogniseTags` | `#тег`, свои слова из настроек | Последним: свои слова могут совпасть с чем угодно выше, и встроенное значение сильнее |

🔴 **Порядок — часть контракта, а не деталь реализации.** `TestRecogniserOrderIsFixed`
держит его: список распознавателей сравнивается с ожидаемым, чтобы перестановка при
рефакторинге краснела, а не меняла поведение молча.

## Дни недели — правило Дениса, записанное точно

```
базовый день = локальная полночь сегодня
целевой индекс = индекс названного дня (пн=0 … вс=6)

без приставки : ближайший день с этим индексом, ВКЛЮЧАЯ сегодня
"следующий"   : ближайший, ВКЛЮЧАЯ сегодня, затем +7
"эта"         : то же, что без приставки
"прошлая"     : ближайший назад, ВКЛЮЧАЯ сегодня, затем −7... нет: ближайший строго назад
```

Проверка на его же примерах, сегодня **вторник 15.09.2026**:

| Ввод | Результат |
|---|---|
| `среда` | **16.09** (завтра) |
| `следующая среда` | **23.09** |
| `вторник` | **15.09** (сегодня) |
| `следующий вторник` | **22.09** |

⚠ **Что делает «сегодня» опасным и как это закрыто.** Сегодняшний день, у которого
время уже прошло, — реальный случай: `вторник 09:00` в 19:00. Старый код молча
переносил на сутки (`!dayGiven && start.Before(now)`). Новый — **не переносит молча**:
день назван явно, значит человек его имел в виду, и карточка подтверждения показывает
дату, которую он увидит до создания. Молчаливый перенос при **неназванном** дне
(`10:00` в 19:00 → завтра) остаётся: там переносить нечего, кроме догадки.

## Сокращения и их цена

Русские двухбуквенные сокращения (`пн`, `вт`, `ср`, `чт`, `пт`, `сб`, `вс`) приняты
Денисом. Токенизация снимает б**о**льшую часть риска: они сработают только как отдельное
слово. Остаточный риск — событие, чьё название и есть одно такое слово (`вс` как
инициалы). Он принят: карточка подтверждения показывает разбор до создания, и это
ровно то, для чего она есть.

# 5. Словарь ключевых слов

`bot/internal/parse/vocab.go`.

| Слово (нормализованное) | Что меняет | Поле API |
|---|---|---|
| `задача` | событие получает связанную задачу, которую можно выполнить | `task_id` (см. §5.1) |
| `весь день`, `allday`, `all day` | событие на весь день, время снимается | `all_day: true` |
| `повтор`, `повторять`, `повторяется` | повтор **без частоты** → карточка спрашивает | `rrule` |
| `ежедневно`, `каждый день`, `daily` | | `FREQ=DAILY` |
| `еженедельно`, `каждую неделю`, `weekly` | | `FREQ=WEEKLY` |
| `каждый <день недели>` | | `FREQ=WEEKLY;BYDAY=WE` |
| `ежемесячно`, `monthly` | | `FREQ=MONTHLY` |
| `синий`/`синее`, `красный`, `зелёный`, `жёлтый`, `фиолетовый`, `оранжевый`, `серый` + `blue`,`red`,… | цвет события | `color` |
| `календарь <слово>` | положить в названный календарь | `calendar_id` |
| `<слово>` = имя существующего календаря | то же | `calendar_id` |
| `напомнить за 15м` / `за 1ч` | своё напоминание | `reminder_offsets` |
| `<имя пресета>` из настроек | пресет напоминаний | `reminder_offsets` |
| `#тег` | тег | `tags` |
| **своё слово** из настроек | тег (или то, на что его назначили) | `tags` |

Прилагательные склоняются, поэтому сравнение идёт по **основе**: `син`, `красн`, `зелён`/`зелен`,
и т.д. — с явным списком окончаний, а не «начинается с». Список основ в одном месте,
тест перебирает формы (`синий`, `синее`, `синяя`, `синим`).

## 5.1 Слово «задача» — что оно на самом деле делает

Денис: *«задача делает событие с возможностью выполнение»*. В API у события есть
`task_id`. Значит бот делает **два вызова**: `POST /api/tasks`, затем `POST /api/events`
с `task_id` созданной задачи.

🔴 **Порядок и отказ.** Если второй вызов отказал, задача уже создана и осталась висеть.
Бот говорит об этом прямо («задача создана, событие — нет»), а не молчит и не пытается
удалить: тихая компенсация, которая сама может отказать, хуже честного сообщения.

⚠ Это же закрывает один из трёх пунктов Дениса от 11.09 («задача и созданное из неё
событие не связаны») — но **только со стороны бота**. Веб остаётся как есть, это работа
v0.4.12.

## 5.2 Календари

Бот не умеет читать список календарей: в `bot/internal/api/client.go` нет `GetCalendars`.
Добавляется вместе с кэшем на время флоу (один запрос на создание, не на токен).

Слово считается именем календаря при **точном совпадении нормализованных имён**.
Частичное совпадение отвергнуто: календарь «Работа» превратил бы каждое «работа»
в названии в смену календаря.

## 5.3 Свои слова

Живут в `settings.bot.keywords` — карта `слово → {field, value}`. Читаются при старте
флоу, пишутся через существующие `MySettings` + `PatchSettings`.

🔴 **Gotcha 21 в полный рост.** `PATCH /api/auth/me` **заменяет** весь blob настроек.
Порядок обязателен: прочитать `GET /api/auth/me` → слить → отправить целиком; **при
сбое чтения не писать вовсе**. Образец уже есть — `MergeSettings` в том же файле, 4 теста.
Наивная запись стирает рабочие часы, тихие часы и пресеты напоминаний, и делает это
с ответом 200.

# 6. Карточка подтверждения

## Форма

```
📅 Оркестр
🗓 Среда, 16 сентября
🕐 14:00–15:00
🔁 повтор — частота не указана
📁 Личный

[✅ Подтвердить]  [✏️ Изменить]  [🗑 Отменить]
```

Показывается **всегда**, включая полностью разобранную строку. Это решение Дениса и
оно же убирает целый класс дефектов: бот больше не создаёт ничего, чего человек не видел.

Строки с неназванным обязательным значением помечены явно (`частота не указана`) и
**подтверждение по ним спрашивает отдельно**: нажатие ✅ при неуказанной частоте
открывает выбор частоты, а не создаёт событие без повтора.

## Изменение

`✏️ Изменить` → клавиатура полей: Название · Дата · Время · Повтор · Календарь ·
Цвет · Теги · Напоминания · Весь день. Выбор поля переводит флоу в режим ввода **этого
одного поля**.

🔴 **Режим сырого ввода — суть пункта 3.** Правка названия и правка тегов принимают
текст **дословно**: `Tokenize` не вызывается вовсе. Поэтому `полдень` в тегах есть тег,
а не время, и название «весь день» остаётся названием. Это не флаг внутри парсера, это
**другая ветка обработки**, и тест утверждает именно отсутствие вызова разбора.

## Состояния

`state.UserState.FlowStep` получает значения:

| Шаг | Что принимает |
|---|---|
| `line` | первую строку (или список) |
| `card` | нажатия трёх кнопок |
| `edit:menu` | выбор поля |
| `edit:title` | сырой текст → название |
| `edit:tags` | сырой текст, разбитый по запятым → теги |
| `edit:date` · `edit:time` · … | текст, разобранный **только** своим распознавателем |
| `ask:freq` · `ask:date` · `ask:time` | кнопки уточнения |
| `list:confirm` | «одна запись или список» |

Черновик живёт в `FlowData["draft"]` одной структурой, а не россыпью ключей: сегодняшняя
россыпь (`title`, `priority`, `minutes`, `due`, `tags`) уже стоила одного дефекта —
`nt_save` с шага визарда молча ничего не делал.

# 7. Кнопка меню прекращает создание

## Дефект

`bot/internal/handlers/handler.go:129` проверяет флоу **раньше** текста:

```go
if us.CurrentFlow != "" {
    h.handleFlowInput(chatID, msg.Text)
    return
}
```

Поэтому «🗓 Календарь», нажатая во время создания, приезжает как название события.

## Починка

Набор подписей reply-клавиатуры сегодня живёт в `keyboards/parity_test.go` — то есть в
`_test.go`, откуда пакет `handlers` его импортировать не может. Он **выносится в
`keyboards` как экспортируемый**, и его читают оба: и новый guard, и тест паритета.
Дублировать строки нельзя — дубль превращает тест паритета в тест самого себя.

```go
// keyboards/menu.go
func MenuLabel(text string) (action string, ok bool)
```

В `HandleMessage` проверка подписи идёт **перед** проверкой флоу: подпись найдена →
`ClearFlow` → выполнить экран.

🔴 **Тест обязан утверждать оба факта**: флоу очищен **и** экран открылся. Тест,
проверяющий только очистку, зелен на боте, который не делает ничего.

# 8. Списки (пункт 5)

## Когда спрашивать

Ввод считается **возможным списком**, если выполнено хотя бы одно:

- в нём больше одной непустой строки;
- в нём есть маркеры перечисления (`1.`, `2)`, `-`, `•`) в начале строк;
- это одна строка с запятыми **и** без распознанного времени (иначе «Ужин, завтра 19:00»
  ломался бы на два).

Тогда бот спрашивает кнопками: **[Одна запись] [Список из N]**. Молча не решает никогда —
это прямое требование Дениса.

## Задачи

Маркеры снимаются, каждая строка — одна задача, каждая проходит `ParseTask`.
Разделитель по запятым используется только когда строк одна.

## События — наследование дня

Его пример:

```
среда
10:00 завтрак
12:00-14:00 оркестр
17:00 работа
четверг
8:00 анализы
```

Правило: **строка, в которой распознан день и НЕ распознано время и не осталось
названия, — это заголовок дня.** Она задаёт текущий день для последующих строк и сама
события не создаёт. Строка со временем создаёт событие на текущем дне. Строка, где есть
и день, и время, и название, создаёт событие и **переносит** текущий день на свой.

Результат на его примере, сегодня вторник 15.09: завтрак/оркестр/работа на **16.09**,
анализы на **17.09**. Всё на этой неделе, потому что приставок нет — §4.

⚠ **Карточка для списка — одна на всех**, со списком строк и теми же тремя кнопками.
«Изменить» для списка правит одну выбранную строку. Отдельная карточка на каждое из
восьми событий — это восемь подтверждений, и это хуже, чем не спрашивать.

🔴 **Частичный отказ.** Создание идёт по одному вызову на запись. Если третий отказал —
бот сообщает, **какие созданы, а какие нет**, и оставляет несозданные в черновике для
повтора. Сводка «создано 5 из 8» без имён бесполезна.

# 9. Гайд по созданию

Сегодня — три строки. Становится коротким списком примеров **с разбором**:

```
Что понимаю:

  Ужин завтра 19:00
    → Ужин, завтра, 19:00–20:00

  среда 14:00-15:00 оркестр повтор
```

# 13. Глобальные ограничения

- `cd bot && go build ./... && go vet ./... && go test ./...` — все три.
- 🔴 `api-go` тоже собрать и прогнать: спека его не трогает, и это должно остаться правдой.
- Никаких новых зависимостей.
- Никаких миграций.
- 🔴 Тест засчитывается, только если показано, что он краснеет.
- `git add` конкретных файлов, никогда `-A`. Никогда со-автор.
- 🔴 Выкатка бота — **ручная**, CI её не делает. Перед словом «готово» — `ls` его `src/`
  на nl-2.
- 🔴 Мерж `develop` → `main` = релиз прода, только по отдельному «да» Дениса.
