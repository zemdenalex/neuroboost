## Section 1 — Bug Fixes

### 1.1 Reflections backend (migration 000008)

**Problem:** `POST /api/events/{id}/reflection` returns 500. `GET /api/reflections` returns 500. Root cause: handler SQL references columns `was_completed` and `was_on_time` that were never added to the `reflection` table.

**Fix:** Create migration `000008_add_reflection_fields.up.sql` / `.down.sql`:

```sql
-- up
ALTER TABLE reflection ADD COLUMN was_completed BOOLEAN DEFAULT false;
ALTER TABLE reflection ADD COLUMN was_on_time BOOLEAN DEFAULT false;

-- down
ALTER TABLE reflection DROP COLUMN was_on_time;
ALTER TABLE reflection DROP COLUMN was_completed;
```

No code changes — handler already expects these columns. Migration auto-runs on API start.

**Verification:** save reflection from event editor → 200. Load `/reflections` → list renders.

### 1.2 Calendar null-pointer on events load

**Problem:** console shows `TypeError: Cannot read properties of null (reading 'events')` during `Calendar-*.js:21`. Events list endpoint returns unexpected shape in some edge cases, unwrap code assumes `{events: [...]}`.

**Fix:** Locate the event list consumer in `web/src/api/events.ts` (or inline client code). Defensive unwrap:

```ts
const events = res?.events ?? res ?? []
```

Add test for empty-range response path. Verify week with no events and week with many events both render.

## Section 2 — Settings UX Rework

**User feedback:** current Settings feel unsafe (unclear if/when changes save), show mobile-only options on desktop, save button buried. Decision from brainstorming:

- **Hybrid save model** — trivial toggles (UI scale, feature flags, theme) auto-save with a small toast; destructive/data actions (export, import, locale) require explicit confirmation.
- **Platform-specific sections hidden** — mobile nav mode never shown on desktop; desktop-only options never shown on mobile. Detection via `useMediaQuery('(max-width: 768px)')` at section level.

**Files:**

- `web/src/pages/Settings/Settings.tsx` — restructure into sections; each section owns its own save behavior
- `web/src/pages/Settings/useAutoSaveSetting.ts` (new) — hook that debounces + writes + shows toast
- `web/src/pages/Settings/sections/*.tsx` — one file per section (Appearance, Features, Mobile Nav, Regional, Data, Account)
- `web/src/contexts/AuthContext.tsx` — `updateProfile` already exists; no changes

**Toast:** reuse existing toast primitive if any; otherwise add a lightweight one (top-right, 2s, "Saved ✓"). No library.

**Sections (desktop vs mobile visibility):**

| Section | Desktop | Mobile |
|---|---|---|
| Appearance (UI scale, theme) | ✓ | ✓ |
| Features (toggles) | ✓ | ✓ |
| Mobile Nav (bottom tabs / hamburger / FAB) | — | ✓ |
| Regional (timezone, locale) | ✓ | ✓ |
| Data (export, import) | ✓ explicit buttons | ✓ |
| Account (logout) | ✓ | ✓ |

**Verification:** toggle UI scale → instant apply + toast. Flip a feature flag → nav item appears/disappears instantly. Open Settings on 375px → see Mobile Nav. Open at 1440px → Mobile Nav section absent.

## Section 3 — Planning Page Redesign

**User feedback:** current layout wastes ~50% of the screen, design feels thin. Decision from brainstorming: **Layout B — Two-Pane**. Unscheduled tasks list on the left (~33%), week visualization on the right (~66%) with capacity meter pinned above the grid.

### Layout (desktop, ≥1024px)

```
┌──────────────────────────────────────────────────────────────┐
│  Weekly Planning    Apr 20 — 26         ← Today →            │
├────────────────────┬─────────────────────────────────────────┤
│  UNSCHEDULED (3)   │  Capacity  ▓▓▓▓░░░░░░  12 / 40 hrs      │
│                    ├─────────────────────────────────────────┤
│  ⊙ Task A  ~1h     │  Mon  Tue  Wed  Thu  Fri  Sat  Sun      │
│  ⊙ Task B  ~2h     │  ┌─┐  ┌─┐  ┌─┐  ┌─┐  ┌─┐  ┌─┐  ┌─┐      │
│  ⊙ Task C  ~30m    │  │ │  │ │  │ │  │ │  │ │  │ │  │ │      │
│                    │  │3│  │5│  │2│  │ │  │2│  │ │  │ │      │
│  [+ quick add]     │  └─┘  └─┘  └─┘  └─┘  └─┘  └─┘  └─┘      │
│                    │  events · events · events (stacked)     │
└────────────────────┴─────────────────────────────────────────┘
```

Day cells show scheduled hours + top 2-3 events (titles truncated). Drag a task from left pane onto a day cell to schedule it (uses existing `scheduleTask` API with default time 09:00). Day cell click → jumps to `/calendar?date=YYYY-MM-DD`.

### Layout (mobile, <1024px)

Stack vertically. Unscheduled list on top (collapsible), week grid below (7 narrow columns, horizontally scrollable if needed, or tap to expand a day).

### Files

- `web/src/pages/Planning/Planning.tsx` — rewrite layout. Keep existing `api/planning` calls.
- `web/src/pages/Planning/WeekOverviewGrid.tsx` (new) — the 7-day grid component
- `web/src/pages/Planning/UnscheduledList.tsx` (new) — left pane task list
- `web/src/pages/Planning/CapacityMeter.tsx` (new) — pinned above grid

**Verification:** page fills viewport at 1920×1080 and 1366×768. Drag a task onto Wed → event created at 09:00 Wed, removed from unscheduled list. Mobile at 375px: stack works, no horizontal scroll on body.

## Section 4 — Telegram Login on Mobile

**Problem:** mobile login page only shows email/password form; Telegram Login Widget is hidden.

**Investigation needed:** check `web/src/pages/Login/Login.tsx` for conditional rendering. Telegram widget may require specific viewport or be hidden behind a media query.

**Fix approach:** show Telegram widget on mobile. Telegram's embedded widget has known responsive issues — if it doesn't render cleanly, use their fallback flow: a "Login with Telegram" button that opens `https://oauth.telegram.org/auth?bot_id=...&origin=...` in a new tab, receives auth via redirect to `/login/telegram/callback`.

Start with the simpler path (just render widget on mobile too) and fall back to redirect if the widget doesn't render properly.

**Files:**

- `web/src/pages/Login/Login.tsx` — remove any `hidden md:block` on Telegram section
- If widget broken on mobile: `web/src/components/Auth/TelegramLoginButton.tsx` (new)

**Verification:** open `/login` on 375px device. Telegram option visible. Login flow completes and lands on `/home`.

## Section 5 — Backup Script Fix

**Problem:** `scripts/backup.sh` fails inside CI deploy ("not a git repository", "docker-compose not found"). Root cause: script used `docker-compose` (v1) instead of `docker compose` (v2), and assumed paths that didn't resolve.

**Fix:**

```bash
#!/bin/bash
set -euo pipefail
BACKUP_DIR="/root/backups"
COMPOSE_DIR="/opt/neuroboost"
TIMESTAMP=$(date +%Y%m%d_%H%M%S)
mkdir -p "$BACKUP_DIR"
docker compose -f "$COMPOSE_DIR/docker-compose.yml" exec -T db \
  pg_dump -U neuroboost neuroboost | gzip > "$BACKUP_DIR/neuroboost_${TIMESTAMP}.sql.gz"
find "$BACKUP_DIR" -name "neuroboost_*.sql.gz" -mtime +7 -delete
echo "Backup complete: neuroboost_${TIMESTAMP}.sql.gz"
```

**Verification:** run manually on server. File appears in `/root/backups/`. CI deploy logs no longer show "Backup failed, continuing deploy..." warning.
