### Факты кода, из-за которых спека такая

- `convert` (`api-go/internal/tasks/convert.go`) копирует название, описание, календарь, теги —
  **не копирует `rrule`**: повторяющаяся задача сейчас молча становится разовым событием.
- 🔴 `INSERT INTO event … timezone` = **`'Europe/Moscow'` захардкожено**. Для пользователя не
  из Москвы событие встаёт не в тот час.
- Напоминания уезжают в событие в **обоих** режимах.
- **«⏰ Запланировать» уже делает «связать»** (`scheduleTask`, `tasks/handlers.go:767`): событие
  с `task_id` + `task.status = 'SCHEDULED'`. Но **не** копирует описание и теги и **не** переносит
  напоминания. Два пути к одной связи с разным поведением.
- Бот показывает только `TODO` → **запланированная задача исчезает из списка**. Против решения
  «остаётся с пометкой».

### A1. API

**`POST /api/tasks/{id}/convert`** (задача → событие) — дополнить, не заменять:

| Поле | Было | Станет |
|---|---|---|
| `mode` | `move` \| `link` | без изменений |
| `repeat` | — | **новое**: `series` \| `once`. Обязательно, если у задачи есть `rrule`; иначе игнорируется |
| `starts_at`, `ends_at` | обязательны | без изменений; при `once` — день ближайшего вхождения |
| часовой пояс события | `'Europe/Moscow'` | 🔴 **из `user.timezone`** |

- `series` → `event.rrule = task.rrule`, начало серии — `starts_at`.
- `once` → событие разовое; при `link` задача-серия остаётся, при `move` 🟢 переносится один день, серия задачи остаётся.
- `link` → **статус задачи не трогается** (не `SCHEDULED`, не прячется).
- Ошибки — существующие коды (`NEEDS_TIME`, `UNKNOWN_MODE`) плюс `REPEAT_CHOICE_REQUIRED`.

**`POST /api/events/{id}/to-task`** (событие → задача) — **новый**:

| Поле | Значение |
|---|---|
| `mode` | `move` (событие удаляется) \| `link` (событие остаётся, `event.task_id` → новая задача) |
| `repeat` | `series` \| `once`, обязательно у повторяющегося события |
| `occurrence` | день вхождения при `once` (`YYYY-MM-DD`), для синтетических id вида `uuid:YYYY-MM-DD` |

Отображение полей — **одно место в коде**, и из него же бот строит карточку:

| Событие | → Задача |
|---|---|
| название, описание, календарь, теги | как есть |
| день начала (в зоне пользователя) | срок — **дата**, не момент |
| длительность | оценка (минуты) |
| час начала | ⚠ **теряется** — у задачи нет часа |
| повтор | при `series` — правило; при `once` — нет |
| напоминания | не переносятся; задача получает пресет по умолчанию |
| цвет | ⚠ **теряется** — назвать на карточке: `цвет → (у задачи нет)` |

Одна транзакция, как у `convert`: полупереход хуже любого исхода.

**Быстрый «⏰ Запланировать»** (`scheduleTask`) идёт **через ту же функцию связи**, что
`convert(link)`: копирует описание и теги, переносит напоминания, **не прячет задачу**.
Сигнатура `POST /api/tasks/{id}/schedule` для веба не меняется.

⚠ `SCHEDULED` остаётся в данных (его знает веб), но бот показывает `TODO` **и** `SCHEDULED`.

### A2. Бот

**Карточка задачи:** `[⏰ Запланировать]` (быстро: слот + длительность, два нажатия, как сейчас) и
`[📅 В календарь]` (полный путь). Если задача связана — строка **«📅 запланирована на вт 15:00»**
и кнопка открыть событие.

**Карточка события:** `[✅ Сделать задачей]`.

**Полный путь, в обе стороны, одна форма:**

1. **Как?** `[🔗 Связать]` — одной строкой, что будет · `[➡️ Перенести]` — одной строкой, что будет
2. **Если повтор:** `[вся серия]` · `[только этот раз]`
3. **Недостающее** (только задача → событие):
   - время: `[Сейчас] [Через час] [Вечером] [Завтра] [✏️ Своё]` — те же слоты, что у быстрой кнопки
   - длительность — только если у задачи нет оценки
   - день — только если у задачи нет срока
4. **Карточка «что чем станет»** — таблица поле → поле, потери помечены ⚠ (как в превью 21.09)
5. `[✅ Готово]` · `[ℹ️ Что это?]` · `[❌ Отмена]`

**Список задач:** связанные — `🔴 позвонить в банк   📅 вт 15:00`.
