## 1. Что это

У каждого дня — **цель N** (по умолчанию 5) и **набор задач дня**. Цвет дня = сколько задач
набора **закрыто в этот день**. Набор собирается так:

1. Заранее: на карточке задачи **📌 В задачи дня** → выбрать день (сегодня · завтра · дата).
2. Утром бот **предлагает** набор: сначала то, что уже добавлено на этот день, затем — добор до N
   (§4). Кнопки **✅ Беру** · **✏️ Поменять**.
3. Подтверждение делает день «взятым». 🔴 День, который так и не взяли, — **⬛** (решение Дениса:
   не выбрал = не сделал).

⚠ Набор короче N считается против N: 2 задачи в наборе, обе сделаны, при N = 5 → 🟥. Это прямо
его «if you don't make 5 things, means you did none» — неполный набор не делает день зелёным.

## 2. Что считается «сделано»

- Только **задачи** (событие «сделанным» быть не может; его связанная задача — может).
- Разовая задача: `completed_at` приходится на **этот день в зоне пользователя**.
- Серия: у дня серии есть `task_occurrence` с `state = 'done'` на **этот** день.
- Закрыта на следующий день — дню набора **не засчитывается**.
- 🔴 Добавить в набор можно только **открытую** задачу: иначе «добавил сделанное — стало зелено».

## 3. Цвет

**N = 5** (слова Дениса, дословно):

| Сделано | 5 | 4 | 3 | 2 | 1 | 0 / не взят |
|---|---|---|---|---|---|---|
| Бот | 🟩 | 🟨 | 🟧 | 🟥 | 🟫 | ⬛ |

**N ≠ 5** — его «1 for 3, 2 for other number of tasks», прочтение подтверждено 22.09:
- **N = 3 → «по оставшимся»** (вариант 1): 3 🟩 · 2 🟨 · 1 🟧 · 0 ⬛.
- **Прочие N → «по доле»** (вариант 2): 100 % 🟩 · ≥ 80 % 🟨 · ≥ 60 % 🟧 · ≥ 40 % 🟥 · > 0 🟫 · 0 ⬛.
  Проверка: при N = 5 доля даёт ровно таблицу выше.

🔴 **Уровень считает сервер, одной функцией** — бот и (потом) веб только рисуют. Тот же принцип,
что у заполненности: иначе однажды бот и веб покажут один день разным цветом.

Веб (следующий релиз) рисует настоящие оттенки по тем же шести уровням.

## 4. Предложение

**Когда** (оба, решение Дениса): в утреннем дайджесте — строкой «📌 Задачи дня: …» с
[✅ Беру] [✏️ Поменять]; и при первом открытии меню за день, если день ещё не взят. У кого
дайджест выключен (`digest_enabled = false`), второй путь — единственный.

**Что** (добор до N, по порядку):
1. уже добавленные на этот день;
2. **вчерашние невыполненные из набора** — чтобы «не сделал» не терялось (подтверждено 22.09);
3. просроченные и со сроком сегодня;
4. дни серий, положенные сегодня;
5. остальные открытые — по приоритету (1 = срочно … 5; 0 = буфер — последним).

**✏️ Поменять** — экран набора: у каждой ❌ убрать, внизу ➕ добавить (список открытых задач).

## 5. Менять после начала дня

- ➕ добавить — **всегда**.
- ❌ убрать — **до 12:00 в зоне пользователя**; после — сервер отвечает `409 TOO_LATE`, бот
  говорит почему. Иначе в 23:00 выкинул невыполненное — и день позеленел.
- Будущие дни — менять свободно.

## 6. Календарь — что показывать в клетке дня

Настройка `settings.bot.calendar_cell` — набор из трёх: **цвет** · **дата** · **занятость**
(`▁…█`, сделано 22.09). Порядок при всех трёх — его слова: **цвет, пробел, дата, пробел,
занятость** → `🟩 21 ▅`. Выбор — в ⚙️ Настройки → 🗓 Календарь.

⚠ **Риск ширины:** 7 кнопок в ряд, у каждой до 6 знаков с эмодзи — Telegram на телефоне может
обрезать до «🟩 2…». Проверить на его телефоне в первом же проходе; запасной вид — без пробелов
(`🟩21▅`).

**Где выбирается** (слова Дениса): **в онбординге** — шаг, который объясняет задачи дня и
занятость и даёт выбрать, что показывать в клетке (с превью), и там же — N. 🟡 Для прошедших
онбординг — **один вопрос при заходе**, как у символа приоритета (кусок B 11.4). До выбора —
как сейчас: дата + занятость.

## 7. Хранение и API

**Миграция `000022_day_commitment`:**

```sql
CREATE TABLE day_commitment (
    user_id     UUID NOT NULL REFERENCES "user"(id) ON DELETE CASCADE,
    day         DATE NOT NULL,              -- день в зоне пользователя (gotcha: дата, не момент)
    task_id     UUID NOT NULL REFERENCES task(id) ON DELETE CASCADE,
    added_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    removed_at  TIMESTAMPTZ,                -- мягкое удаление: «убрал до полудня» видно
    PRIMARY KEY (user_id, day, task_id)
);
CREATE TABLE day_commitment_day (          -- «день взят»: подтверждение предложения
    user_id      UUID NOT NULL REFERENCES "user"(id) ON DELETE CASCADE,
    day          DATE NOT NULL,
    confirmed_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    PRIMARY KEY (user_id, day)
);
```

Цель N — `settings.day_tasks_target` (верхний уровень, не `bot.*`: её прочтёт и веб; сервер
нужен ей для уровня). По умолчанию 5, допустимо 3–7.

**Ручки** (все — день в зоне пользователя, `YYYY-MM-DD`):

| Ручка | Что |
|---|---|
| `GET /api/day-tasks?from&to` | по дням: `{day, target, confirmed, items:[{task_id,title,done}], done, level}` — ≤ 62 дня |
| `GET /api/day-tasks/proposal?day` | предложение по §4, ничего не пишет |
| `POST /api/day-tasks/confirm` `{day, task_ids}` | взять день этим набором |
| `POST /api/day-tasks` `{day, task_id}` | добавить (только открытая, своя или из видимого календаря) |
| `DELETE /api/day-tasks/{day}/{task_id}` | убрать; `409 TOO_LATE` после 12:00 сегодняшнего дня |

`level`: `0…5` (⬛🟫🟥🟧🟨🟩) — одна функция `daytasks.Level(done, target)` с тестами на все N.

## 8. Бот

- Меню: **📌 Задачи дня** — сегодня: набор с ✅/⬜, цвет, счёт `3 из 5`, ← → по дням.
- Карточка задачи: **📌 В задачи дня** → сегодня · завтра · ✏️ дата.
- Утро: строка в дайджесте + кнопки; первый заход — тот же экран, если день не взят.
- ⚙️ Настройки: **🎯 Задач в день** (3–7) · **🗓 Календарь** (что в клетке).
- Онбординг: шаг «📌 Задачи дня» после шкалы — объяснение, N, вид клетки с превью;
  прошедшим онбординг — один раз при заходе.
- `ℹ️ Что это?` на экране задач дня — текст в реестр (кусок C 11.4), скан это потребует сам.

## 9. Приёмка

- [ ] N = 5: сделано 5/4/3/2/1/0 → 🟩🟨🟧🟥🟫⬛; день без подтверждения → ⬛
- [ ] Набор из 2 задач, обе сделаны, N = 5 → 🟥
- [ ] Задача закрыта завтра → сегодняшнему дню не засчитана
- [ ] Серия: «✅ на сегодня» засчитывает день серии в набор сегодняшнего дня
- [ ] Добавить сделанную задачу → отказ
- [ ] Убрать в 11:59 — можно; в 12:00 — `409 TOO_LATE` и понятная фраза (зона пользователя, тест с `America/New_York`)
- [ ] Предложение: добавленные заранее — первыми; добор до N по §4
- [ ] Дайджест выключен → предложение при первом заходе; включён → и там, и там, но после ✅ второй раз не спрашивает
- [ ] Календарь: настройка из трёх, при всех — `🟩 21 ▅`; уровень в клетке = уровень на экране задач дня
- [ ] N = 3 и N = 7 — уровни по §3
- [ ] Онбординг спрашивает N и вид клетки; старый пользователь — один раз, выбор снимает вопрос

## 10. Срезы

D1 API (миграция, `Level`, ручки, тесты через HTTP против БД) → D2 бот: экран, 📌 на карточке,
настройка N → D3 утро: дайджест + первый заход → D4 клетка календаря и её настройка →
**следующий релиз:** веб.

## Не входит

- Веб — следующий релиз
- «Задачи дня» как сущность в статистике (строка «взятых дней / зелёных») — после D4, если попросит
- События в наборе (решено: только задачи)
- Серии побед, streak'и, награды
- Уведомление «до конца дня осталось N» — не просил
