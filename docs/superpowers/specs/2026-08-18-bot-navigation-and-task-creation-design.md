# Бот: навигация inline-first, календарь и создание задачи

**Статус:** черновик на ревью Дениса · **Дата:** 2026-08-18
**Разбор с доказательствами:** `docs/razbor-bot-telegram-native-2026-08-18.md` §5
**Соседняя спека:** `2026-08-18-bot-telegram-native-and-sharing-design.md` (библиотека, шаринг, списки)

## Откуда взялась

Три претензии Дениса после ручного прохода **dev**-бота 19.08, дословно:

> «tasks creation is bad, calendar view is much worse than what it was in previous versions,
> menu doesn't show extra buttons, only reffer to keyboard buttons»

🔴 **Проверено, какого бота он жал:** dev. На nl-2 у `/opt/neuroboost-bot/src/internal/handlers/`
есть `schedule.go`, `settings.go`, `planning.go` — значит новый месячный календарь и экран
рабочих часов он **видел**, и всё равно назвал хуже. То есть чинить, а не «донести до него».

⚠ Претензия «settings don't work» в эту спеку **не входит**: экран рабочих часов на dev есть
и работает, а что именно в нём не сработало — Денис не назвал. Спрашивать открыто, а не
угадывать: без его ответа любая правка здесь — стрельба по площадям.

## Цель

Меню перестаёт быть надписью, отсылающей к кнопке. Экран, на котором ты стоишь, показывает
то, что с него можно сделать. Задача заводится одной строкой, а поля добираются по желанию.

## Границы — что НЕ входит

- ❌ Заметки — своя спека, там миграция и новый роут.
- ❌ Библиотека, шаринг, списки-чеклисты — соседняя спека.
- ❌ Mini App.
- ❌ Экран настроек сверх того, что уже есть (см. ⚠ выше).
- ❌ Правки в `api-go`: **всё в этой спеке делается только в модуле `bot/`.** API уже
  принимает `description`, `due_date`, `estimated_minutes`, `tags`, `reminder_offsets`
  (`api-go/internal/tasks/types.go`, `CreateTaskRequest`).
- ❌ Прод-релиз без отдельного «да» Дениса.

## Глобальные ограничения

- Модуль один: `cd bot && go build ./... && go vet ./... && go test ./...`.
- 🔴 `callback_data` — **64 байта**, UUID = 36. Каждая новая клавиатура получает тест на длину.
- 🔴 Утверждение о v0.2.1 цитирует строку `bot.action` в
  `_legacy/snapshots-v0.0.1-v0.4.0/v0.2.1/apps/bot/src/index.mjs`, **никогда** не клавиатуру
  в `keyboards.mjs`. Клавиатура соврала дважды: сперва «пять потерянных возможностей» (двух
  не было), затем «четыре быстрых действия дня» (все четыре — кнопки без обработчика).
- 🔴 Тест засчитывается, только если показано, что он краснеет.
- 🔴 Токен не течёт в лог: ошибки — через `logsafe.Redact`.
- `git add` конкретных файлов, со-автор Claude/Anthropic — никогда.

# Часть 1 — форма навигации

## Решение Дениса, дословно

> «reply (keyboard buttons) must have menu, calendar, events, tasks… each of keyboard buttons
> open inline menus. Actually I think 6 buttons, the ones I said + add new (anything) and settings»

То есть **гибрид с жёстким правилом**: reply-клавиатура — это шесть постоянных **входов**,
и ничего кроме входов; всё, что происходит дальше, — inline.

## Reply-клавиатура: ровно шесть кнопок

```
[ 🏠 Меню      ][ 🗓 Календарь ]
[ 📅 События   ][ 📋 Задачи    ]
[ ➕ Создать   ][ ⚙️ Настройки ]
```

Сегодня их девять и они смешивают входы с действиями (`📝 Note`, `➕ New Task`,
`📅 New Event`, `🗂 Planning`, `📊 Stats` — `keyboards.go`, `MainMenu`). После правки:

| Было (reply) | Стало |
|---|---|
| `🎯 Today` | внутри `🏠 Меню` и `📅 События` |
| `📋 Tasks` | `📋 Задачи` — остаётся входом |
| `📝 Note` | inline внутри `➕ Создать` (сущность — в спеке заметок) |
| `➕ New Task` | inline внутри `➕ Создать` |
| `📅 New Event` | inline внутри `➕ Создать` |
| `🗓 Calendar` | `🗓 Календарь` — остаётся входом |
| `🗂 Planning` | inline внутри `🏠 Меню` |
| `📊 Stats` | inline внутри `🏠 Меню` |
| `⚙️ Settings` | `⚙️ Настройки` — остаётся входом |

🟡 **`📅 События` — новый экран, и его надо определить, потому что он не то же, что календарь:**
- `🗓 Календарь` — **сетка месяца** и день по нажатию. Вопрос «что у меня 24-го».
- `📅 События` — **повестка: ближайшие события списком**, начиная с сегодня. Вопрос «что дальше».

Второй экран сегодня не существует ни в боте, ни в вебе (см. `docs/razbor-mobilnyy-kalendar-2026-08-19.md`
§3, вариант B — «единственный из четырёх, которого нет ни в вебе, ни в боте»). Он дешёвый:
одна выборка `GET /api/events` за две недели вперёд плюс та же отрисовка, что у дня.

## Правило, из которого следует всё остальное

🔴 **Ни один экран не отсылает к reply-кнопке словами.** Если с экрана можно что-то сделать —
там стоит inline-кнопка, которая это делает.

Нарушения сегодня, поимённо:

| Файл | Строка-нарушитель | Чем становится |
|---|---|---|
| `tasks.go`, `handleTasks` | «No tasks — Use ➕ New Task to create one.» | кнопка `➕ Новая задача` |
| `calendar.go`, `handleCalendarDay` | «Пусто. Создать — **📅 New Event**.» | кнопка `➕ Событие на этот день` |
| `handler.go`, `HandleMessage` default | «Use the menu buttons or /start» | текст остаётся, но с inline-меню под ним |
| `commands.go`, `handleStart` | «Use the menu below to get started» | само меню становится inline, а не подписью к reply |

## `🏠 Меню` — живой экран, а не приветствие

Сегодня `handleStart` шлёт неизменную строку и reply-клавиатуру. Становится inline-экраном,
который **говорит состояние** и правится на месте:

```
🧠 NeuroBoost · вторник, 18 августа
─────────────────────────────
Сегодня: 3 события · 2 задачи
Ближайшее: 14:00 Созвон

[ 🎯 Сегодня  ][ 🗂 Планирование ]
[ 📊 Статистика ][ ⚙️ Настройки  ]
```

⚠ **Стоимость, которую надо назвать:** это два запроса (`GET /api/events` на день,
`GET /api/tasks`) на каждое открытие меню. Приемлемо: меню открывают руками, не тикером.
Если запрос упал — меню всё равно рисуется, со строкой «не смог загрузить сводку»; **экран
навигации не имеет права не открыться из-за сводки**.

## Навигация правит сообщение, а не плодит новые

Сегодня из всех экранов на месте правится только месячная сетка (`editHTMLWithKeyboard`
зовут `showMonth` и `handleCalendarNav`). Остальные шлют новое сообщение.

Становится: **всякий переход по inline-кнопке правит то сообщение, на котором нажали.**
Новое сообщение шлётся только когда его нет — то есть на reply-кнопку и на `/start`.

Для этого обработчики получают `messageID` — сейчас его принимают только двое
(`showMonth`, `handleCalendarNav`).

🔴 **Сообщение может оказаться неправимым** (старше 48 часов — Telegram запрещает правку).
Тогда бот шлёт новое, а не молчит. Ошибку `"message is not modified"` по-прежнему глотаем.

# Часть 2 — три настоящие регрессии календаря

Проверено по обработчикам v0.2.1, не по клавиатурам (разбор §5).

| Возможность | v0.2.1 | Сегодня | Чинится |
|---|---|---|---|
| День открывается **правкой того же сообщения** | 🟢 `index.mjs:801` `editMessageText` | 🔴 новое сообщение (`calendar.go:194` `sendHTMLWithKeyboard`) | Частью 1 целиком |
| Листание дней ⬅️/➡️ из дня | 🟢 обработчик `calendar_day_` (`index.mjs:750`) живой | 🔴 нет | `cal_day_<ISO>` уже несёт дату — соседний день считается на месте |
| Прыжок «📅 Сегодня» из сетки | 🟢 живой | 🔴 нет | Кнопка в нижнем ряду `MonthGrid` |

🔴 **Чего в v0.2.1 НЕ было, вопреки первому впечатлению:** «➕ New Event на этот день»,
«📋 Tasks for Day», «Day Stats» — эти кнопки в `keyboards.mjs:288–297` есть, а обработчиков
`new_event_`, `day_tasks_`, `day_stats_` в `index.mjs` **нет ни одного**. Нажатие не делало
ничего уже тогда. В список регрессий они не идут.

⚠ Но `➕ Событие на этот день` мы всё равно делаем — не как возврат потери, а как правило
«экран не отсылает словами» (часть 1). Разница в основании важна: возвращать несуществующее
прошлое — это как раз тот класс ошибки, который стоил двух ночей.

## Вид дня после правки

```
📅 24 августа, воскресенье
─────────────────────────────
🕐 10:00 — Завтрак
🕐 14:00 — Созвон по проекту

[ ⬅ 23 авг ][ Сегодня ][ 25 авг ➡ ]
[ ➕ Событие на этот день        ]
[ « К месяцу ][ 🏠 Меню          ]
```

**Бюджет callback:** `cal_day_2026-08-24` = 8 + 10 = **18 байт** ✓ — запас огромный, дата
влезает целиком, состояние в сессии не нужно.

# Часть 3 — создание задачи

## Решение Дениса

Оба пути: **строка — быстрый, мастер — по кнопке «Подробнее»**, и *«ничто не должно быть
обязательным, должна быть кнопка пропустить и добавить позже»*.

## Быстрый путь

`➕ Создать` → `📋 Задача` → бот ждёт строку. Строка разбирается, показывается карточка:

```
Ты: позвонить в банк завтра 30м !1

  ➕ Новая задача
  🔴 Позвонить в банк
  📅 завтра · ⏱ 30м

  [ ✅ Создать                ]
  [ 📝 Подробнее (по шагам)   ]
  [ ❌ Отмена                 ]
```

🔴 **`✅ Создать` доступна сразу** — это и есть «ничто не обязательно». Ничего не написал
кроме заголовка — задача создастся с приоритетом по умолчанию и без срока.

### Разбор строки

Образец уже есть и его надо повторить, а не изобретать: `bot/internal/parse/event.go`
разбирает «Ужин завтра 19:00» для событий и покрыт тестами. Задаче нужны свои маркеры:

| Маркер | Значение | Пример |
|---|---|---|
| `сегодня`, `завтра`, `в пятницу`, `24.08` | `due_date` | `купить билеты завтра` |
| `15м`, `30м`, `1ч`, `90м` | `estimated_minutes` | `созвон 30м` |
| `!1` … `!5`, `!0` | `priority` | `позвонить !1` |
| `#тег` | `tags` | `отчёт #работа` |

⚠ **Инверсия приоритета — ловушка, которую надо назвать в коде:** 1 = Emergency, 5 = If
Possible, 0 = Buffer. `!1` — это самое срочное, не самое слабое (gotcha 4).

🔴 **Неразобранное остаётся в заголовке, а не выбрасывается.** Если человек написал
«позвонить в банк насчёт !срочно», а `!срочно` не маркер — оно часть названия. Молча
отрезать кусок названия хуже, чем не разобрать вовсе.

## Мастер «Подробнее»

Шаги: приоритет → срок → оценка → теги. У каждого — `⏭ Пропустить` и `✅ Создать сейчас`:

```
🎯 Приоритет?
[🔴 1][🟠 2][🟡 3]
[🟢 4][⚪ 5][🔵 0]
[ ⏭ Пропустить ][ ✅ Создать сейчас ]
```

Мастер стартует **из карточки**, то есть уже с тем, что разобрано из строки: шаг, значение
которого уже известно, показывает его текущим и позволяет заменить.

## Карточка задачи получает недостающие правки

`TaskActions` (`keyboards.go`) сегодня: `⏰ Запланировать`, `✅ Done`, `🗑 Delete`, `« Back`.
Добавляются `📅 Срок`, `⏱ Оценка`, `🏷 Теги` — те же экраны, что шаги мастера, что и есть
довод переиспользовать их, а не писать дважды.

**Бюджет callback:** `task_due_<uuid>` = 9 + 36 = **45** ✓, `task_est_<uuid>` = **45** ✓,
`task_tag_<uuid>` = **45** ✓.

# Ошибки

| Что произошло | Что видит человек |
|---|---|
| API не ответил при открытии меню | Меню рисуется, вместо сводки — «не смог загрузить сводку». Навигация не отказывает из-за данных |
| Сообщение старше 48 часов, правка запрещена | Шлём новое сообщение вместо правки. Молчать нельзя |
| Строка задачи не разобралась совсем | Вся строка — заголовок. Это не ошибка, это самый частый случай |
| Нажали `✅ Создать` дважды | Вторая создаёт вторую задачу. ⚠ Не защищаемся: карточка после первого нажатия заменяется на результат, и второй кнопки уже нет |
| Задача создалась, но карточка не нарисовалась | Задача **создана** — говорим об этом текстом с id, а не «не получилось» |

# Тестирование

Всё — чистые функции, поэтому проверяемо без Telegram:

- `parseTaskLine(s) → (title, priority, due, minutes, tags)`: пустая строка · только заголовок ·
  `!1` против `!5` (**инверсия**: тест утверждает, что `!1` строже) · `#тег` в середине ·
  неразобранный `!срочно` **остался в заголовке** · русский заголовок режется по рунам, не по байтам.
- `nextDay/prevDay` для листания: переход через конец месяца, через 29 февраля, через переход
  на зимнее время в Europe/Moscow.
- Длина `callback_data` на каждую новую клавиатуру.
- 🔴 **Тест «ни один экран не отсылает к reply-кнопке»**: проход по всем строкам,
  отдаваемым обработчиками, с поиском подстрок `New Task`, `New Event`, «Use the menu».
  Этот тест — единственное, что не даст правилу протухнуть при следующей правке текстов.
  Его надо показать красным на сегодняшнем коде: он **обязан** найти четыре нарушения
  из таблицы части 1.


Логи — только через фильтр: `docker logs … 2>&1 | sed -E 's/bot[0-9]+:[A-Za-z0-9_-]+/bot<REDACTED>/g'`

🔴 **Приёмка этой спеки — не тесты, а проход Дениса руками.** Она вся про то, что человек
видит на экране; зелёный `go test` не отвечает на вопрос «стало ли лучше».
