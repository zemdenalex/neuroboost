# Заметки перестают быть задачами

**Статус:** черновик на ревью Дениса · **Дата:** 2026-08-18
**Разбор:** `docs/razbor-bot-telegram-native-2026-08-18.md`
**Соседние спеки:** `2026-08-18-bot-navigation-and-task-creation-design.md`,
`2026-08-18-bot-telegram-native-and-sharing-design.md`

## Откуда взялась

Денис после ручного прохода 19.08: *«notes are tasks for some reason»*. И, увидев разбор:
*«yeah, also I think we already had it and used it»*.

🔴 **Он прав дважды.** Проверено:

1. **Сегодня заметка — это задача.** `bot/internal/handlers/flows.go`, `handleNoteFlow`
   вызывает `CreateTask(…, Priority: 5, Status: "TODO")`. То есть каждая заметка попадает в
   список задач и требует, чтобы её «сделали».
2. **Раньше сущность была.** v0.2.1: `POST /notes/quick` и `GET /notes/quick`
   (`_legacy/snapshots-v0.0.1-v0.4.0/v0.2.1/apps/api/src/server.mjs:538,577`), таблица
   `quickNote` через prisma, поля `body`, `tags[]`, `source`. Бот звал её
   (`apps/bot/src/api-client.mjs:89`), веб звал её (`apps/web/src/api.ts:180`).
3. **В сегодняшнем API заметок нет вовсе** — ни одного роута в `api-go/cmd/api/main.go`,
   ни одной таблицы в миграциях (единственные вхождения `note` — `notes TEXT` внутри чужой
   таблицы в baseline и `admin_notes` у feedback).

Значит это **потеря переписывания**, а не недоделка. И её не было ни в одном списке потерь —
оба списка строились по кнопкам бота, а `POST /notes/quick` кнопкой не был.

## Цель

Быстро записать мысль с телефона так, чтобы она не притворялась задачей и не мусорила
в списке дел.

## Границы — что НЕ входит

- ❌ **Веб.** Экран заметок в `web/` — отдельным заходом. Эта спека доводит API и бот.
- ❌ **Поиск полнотекстом.** Фильтр по тегу — да; `tsvector` — нет.
- ❌ **Превращение заметки в задачу или событие.** Очевидное продолжение, но не здесь.
- ❌ **Шаринг заметок.** Заметка личная. Календарной привязки у неё нет.
- ❌ **Обратная миграция старых «заметок-задач»** — см. отдельный раздел, там причина.
- ❌ Прод-релиз без отдельного «да» Дениса.

## Глобальные ограничения

- Два модуля, две команды: `cd api-go && go build ./... && go vet ./... && go test ./...`
  и то же в `cd bot`.
- Существующие миграции не правим. Следующая свободная — **000017** (проверено:
  `ls api-go/migrations/*.up.sql | wc -l` = 16).
- 🔴 **`CREATE TABLE IF NOT EXISTS` принимает чужую таблицу и молчит** — это уронило прод
  18.08 (gotcha 18). Для новой таблицы `note` риск тот же, если имя где-то уже занято.
  Поэтому в тестах есть проверка **формы**, а не только факта существования.
- Запросы pgx только параметризованные.
- 🔴 Тест засчитывается, только если показано, что он краснеет.
- `git add` конкретных файлов, со-автор Claude/Anthropic — никогда.

# Часть 1 — данные

## Миграция 000017

```sql
CREATE TABLE IF NOT EXISTS note (
    id         UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id    UUID NOT NULL REFERENCES "user"(id) ON DELETE CASCADE,
    body       TEXT NOT NULL,
    tags       TEXT[] NOT NULL DEFAULT '{}',
    source     TEXT NOT NULL DEFAULT 'web',
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_note_user_created ON note (user_id, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_note_tags ON note USING GIN (tags);
```

**Почему именно так:**

- `body`, `tags`, `source` — те же три поля, что были у `quickNote` в v0.2.1. Форма
  проверена временем и её незачем изобретать заново.
- `user_id NOT NULL` — в v0.2.1 заметки были **общими на всю базу** (в `POST /notes/quick`
  нет никакого владельца). Это годилось для приложения на одного; сегодня в базе больше
  одного человека, и заметка без владельца — это заметка, видимая всем.
- Индекс по `(user_id, created_at DESC)` — под единственный частый запрос: последние N моих.
- GIN по `tags` — под фильтр по тегу.
- ❌ **`calendar_id` НЕ добавляем.** Заметка не в календаре и шарингу не подлежит (Границы).
  Колонка «на будущее» — это колонка, про которую через месяц никто не помнит, зачем она.

## 🔴 Обратной миграции старых заметок не будет, и это не лень

Заметки, заведённые ботом до сих пор, лежат в `task` как `priority = 5, status = 'TODO'`.
**Отличить их от настоящих задач с низким приоритетом нечем**: `handleNoteFlow` не ставил
ни тега, ни описания, ни какого-либо признака источника.

Любой запрос, который «перенесёт заметки», на самом деле перенесёт **все** задачи с
приоритетом 5 — то есть утащит из списка дел настоящие задачи, и человек об этом узнает,
когда что-то не сделает.

**Поэтому:** старое остаётся задачами. Новое пишется заметками. Если Денис захочет
разобрать старое — это ручной проход по списку, а не SQL.

# Часть 2 — API

Роуты рядом с остальными в `api-go/cmd/api/main.go`, внутри блока с авторизацией:

```
GET    /api/notes?limit=20&tag=идеи
POST   /api/notes
PATCH  /api/notes/{id}
DELETE /api/notes/{id}
```

Пакет `api-go/internal/notes/` по образцу соседей: `handlers.go` + `types.go`,
ответы через `util.RespondJSON` / `util.RespondError`, пользователь из
`middleware.UserIDFromContext`.

```go
type CreateNoteRequest struct {
    Body   string   `json:"body"`
    Tags   []string `json:"tags,omitempty"`
    Source string   `json:"source,omitempty"` // "bot" | "web"; пусто → "web"
}

type Note struct {
    ID        string    `json:"id"`
    Body      string    `json:"body"`
    Tags      []string  `json:"tags"`
    Source    string    `json:"source"`
    CreatedAt time.Time `json:"created_at"`
    UpdatedAt time.Time `json:"updated_at"`
}
```

## Теги из `#хештегов` — и одно отличие от v0.2.1

Из тела вынимаются `#слова` и складываются в `tags`, как было раньше.

🔴 **Но автоматического тега `quick` не будет.** v0.2.1 ставил `['quick', ...найденные]`
(`server.mjs:551`). Тег, стоящий на **каждой** записи, ничего не различает — он занимает
место в интерфейсе и в голове, не отвечая ни на один вопрос. Если понадобится «только
быстрые» — это `source = 'bot'`, и оно уже есть.

⚠ **Кириллица в теге обязана работать.** `#идеи` — это `\w` только при Unicode-режиме
регулярного выражения. Голое `[a-zA-Z0-9_]` молча вернёт пустой список тегов на русском
тексте, то есть на **всех** заметках Дениса. Тест на это — обязателен, и он должен
краснеть с ASCII-версией шаблона.

## Массивы

`tags` из API — **никогда `null`**, всегда `[]` (правило проекта). Для `TEXT[] NOT NULL
DEFAULT '{}'` это получается само, но тест это утверждает: во фронте и в боте `nil`-слайс
и пустой ведут себя по-разному.

# Часть 3 — бот

## Куда попадает

По спеке навигации `📝 Заметка` живёт inline внутри `➕ Создать`, а просмотр — экраном
`📝 Заметки` из `🏠 Меню`.

⚠ Если спека навигации ещё не сделана, заметки цепляются к сегодняшней reply-кнопке
`📝 Note` — часть 3 **не блокируется** навигацией, меняется только вход.

## Запись

`➕ Создать` → `📝 Заметка` → бот ждёт текст → `POST /api/notes` с `source: "bot"`.

Ответ подтверждает **тем, что записано**, а не общей фразой:

```
✅ Записал
«купить кабель usb-c»
🏷 покупки

[ 📝 Ещё заметку ][ 📋 Все заметки ]
[ 🏠 Меню                          ]
```

Сегодня ответ — `«✅ Note saved as task!»`, и он честно называет дефект вслух.

## Просмотр

```
📝 Заметки · 12
─────────────────────────────
• купить кабель usb-c #покупки
• идея: недельный обзор #nb
• спросить про отпуск

[ 🔍 По тегу ][ ➕ Новая ]
[ 🏠 Меню               ]
```

Список — текстом, не кнопками: у заметки нет действия, ради которого её надо нажимать.
Удаление — редкое, живёт за `🔍 По тегу` → выбор заметки. **Не делаем кнопку на каждую
строку только потому, что у задач она есть**: это разные сущности, и одинаковый вид
внушал бы, что заметку надо «закрыть».

**Бюджет callback:** `note_del_<uuid>` = 9 + 36 = **45** ✓ из 64.

# Ошибки

| Что произошло | Что видит человек |
|---|---|
| API не ответил при записи | «⚠️ Не сохранил. Твой текст: «…» — пришли ещё раз или скопируй». 🔴 **Текст возвращается человеку**, иначе мысль, ради которой всё затевалось, теряется |
| Пустой текст | «Пустую заметку не записываю» — и остаёмся в том же шаге |
| Тело длиннее лимита сообщения Telegram при показе | Список режется по рунам с «…», счётчик в заголовке говорит настоящее число |
| Тегов не нашлось | Не ошибка: `tags` = `[]`, заметка сохраняется |
| Заметка удалена в другом клиенте | Список её просто не покажет |

# Тестирование

**API (`api-go`):**
- `extractTags`: `#покупки` **кириллицей** · несколько тегов · тег в начале, середине, конце ·
  `#` без слова · дубликаты схлопываются · регистр. 🔴 Тест обязан краснеть, если шаблон
  заменить на ASCII-версию — иначе он не доказывает главного.
- Против настоящей базы: заметка одного пользователя **не видна** другому. Это единственный
  тест, доказывающий, что `user_id` действительно в запросе, а не только в схеме.
- 🔴 **Проверка формы таблицы**, а не только её наличия — спрашиваем у базы список колонок
  `note` и сверяем с ожидаемым. Основание — gotcha 18: `CREATE TABLE IF NOT EXISTS` принял
  чужую таблицу и записал успех, а тесты этого не поймали **по построению**, потому что
  каждая тестовая база строится прогоном миграций с нуля.
- `tags` в ответе — `[]`, не `null`.

**Бот (`bot`):** формирование текста списка — чистой функцией: пусто · один · счётчик ·
рунный обрез длинного тела.

# Выкатка

Порядок обязателен и он не тот, в котором пишется код:

1. **API первым.** Миграция + роуты уезжают релизом прода **по отдельному «да» Дениса**
   (мерж `develop` → `main` = релиз).
2. **Бот вторым**, руками на nl-2 — CI его не деплоит:

```bash
ssh -i ~/.ssh/ufo_servers root@185.214.10.107 'cd /opt/neuroboost-bot && mv src src.bak-<дата>'
git archive --prefix=src/ <ref>:bot | ssh -i ~/.ssh/ufo_servers root@185.214.10.107 'cd /opt/neuroboost-bot && tar x'
ssh -i ~/.ssh/ufo_servers root@185.214.10.107 'cd /opt/neuroboost-bot && docker compose up -d --build bot'
ssh -i ~/.ssh/ufo_servers root@185.214.10.107 'ls /opt/neuroboost-bot/src/internal/handlers/'
```

🔴 **Бот, выкаченный раньше API, ломает кнопку `📝 Заметка` для всех** — она пойдёт в роут,
которого на сервере ещё нет. Порядок здесь — не аккуратность, а условие работоспособности.
