## 1. Что получает человек

1. **Страница `/day-tasks` «📌 Задачи дня»** — тот же экран, что в боте:
   - день с ◀ ▶, квадрат уровня и «3 из 5»;
   - день не взят → предложенный набор и **«Беру»**; взят → задачи с ⬜/✅ по нажатию;
   - **Поменять**: убрать задачу (сегодня — до 12:00, будущее — всегда, прошлое — никогда),
     добавить из открытых задач;
   - прошедший день только смотрится.
2. **Цвет дня в шапке недели календаря** — квадрат рядом с числом у каждого дня. Это «цвет везде»
   для веба: месячного вида в вебе **нет** (`MonthView` — заглушка в одну строку).
3. **Секция настроек «📌 Задачи дня»**: включены/выключены · задач в день 3–7 · красить ли дни до
   начала. Те же ключи верхнего уровня, что пишет бот: `day_tasks_enabled`,
   `day_tasks_target`, `day_tasks_paint_before`.
4. **Выключены** → нет пункта в навигации, нет квадратов в календаре, страница `/day-tasks`
   говорит «выключены» и даёт включить. Данные не трогаются.

## 2. API — ничего нового

Все ручки уже есть (`api-go/cmd/api/main.go:173–177`), поле `before_start` — с D3.
🔴 **Ночью `api-go` не трогать**: push пересобирает staging, с которым говорит dev-бот, и
Денис утром проходит чеклист D3 по этому API.

| Действие | Запрос |
|---|---|
| дни | `GET /api/day-tasks?from&to` → `Day[]` (`day, target, confirmed, items[], done, level, before_start`) |
| предложение | `GET /api/day-tasks/proposal?day` → `DayItem[]` |
| взять | `POST /api/day-tasks/confirm {day, task_ids}` (пустой набор = `[]`, не `null`) |
| добавить | `POST /api/day-tasks {day, task_id}` |
| убрать | `DELETE /api/day-tasks/{day}/{task_id}` |
| отметить | серия: `POST /api/tasks/{id}/occurrences {state:"done", date}`; разовая: `PATCH` status `DONE` |

Отказы сервера: `TOO_LATE` (после 12:00 / прошлое), `NOT_OPEN`, `NOT_AN_OCCURRENCE`,
`TASK_NOT_FOUND`, `RANGE_TOO_LARGE` (> 62 дней). Показываются человеческой фразой.

## 3. Одно правило цвета — чистая функция

`lib/dayTasks/dayColour.ts` — порт `bot/internal/handlers/daycolour.go` **с теми же кейсами
таблицы**, чтобы два клиента не разошлись:

- будущее — без цвета; сегодня — без цвета, пока не взят;
- `before_start && !paintBefore` — без цвета;
- иначе `level` → `⬛ 🟫 🟥 🟧 🟨 🟩` (0…5, вне диапазона — ⬛, как `format.DayLevel`).

## 4. Чьё «сегодня»

🔴 **Сегодня — в зоне пользователя (`user.timezone`), не браузера** (урок
`learning-the-right-time-in-the-wrong-zone`: три дефекта одной формы за одну ночь).
Строка `YYYY-MM-DD` берётся через `Intl` в зоне пользователя.

## 5. Запись настроек — gotcha 21, теперь с двумя писателями

`updateSettings` (`AuthContext.tsx:204`) строит новый blob из **памяти вкладки** и заменяет весь
blob на сервере. Бот теперь сам пишет `day_tasks_*` и `settings.bot.*` → веб, открытый до этого,
**откатит** их первым же сохранением любой настройки.

Решение: `updateSettings` перед записью **читает `GET /api/auth/me`** и сливает поверх свежего,
а не поверх памяти; чтение не удалось → **не писать** (как `MergeSettings` бота). Тест: сервер
держит ключ, которого нет в памяти вкладки → после сохранения ключ цел.
⚠ `web/e2e/settings-race.spec.ts` — гонка своих же сохранений; слияние поверх свежего её не
ломает (последняя запись всё равно побеждает), но прогон e2e в CI это подтвердит.

ru + en на каждый ключ (`i18n/locales/{ru,en}/daytasks.json`). Без длинных тире и жаргона.

## 7. Решения на проверку Денису (вкус — его)

- 🟡 Пункт «📌 Задачи дня» в навигации — рядом с «Задачи»; на мобиле — в листе FAB, не в нижней
  панели (там 4–5 мест и они заняты).
- 🟡 Квадрат в шапке недели — эмодзи тем же набором, что в боте, слева от числа.
- 🟡 Страница — одна колонка, стиль секций как в настройках (`bg-zinc-900 border-zinc-800`).

## Не входит

- Месячный вид в вебе (своя фича; `MonthView` — заглушка)
- Выбор «что в клетке» (`calendar_cell`) — клетки месяца в вебе нет
- Онбординг задач дня в вебе
- Строка задач дня на «Главной» (`/home`) — после его review
- Задачи дня в статистике
- Любые правки `api-go`
