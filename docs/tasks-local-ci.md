# Задачи: CI и деплой с компьютера, GitHub только хранит код

Денис, 25.10.2026: *«Надо заменить ci локальным тестами и ci с компьютера, мы можем это сделать без гитхаба?»*. Выбрано (после разбора рисков): **локальный CI и деплой, GitHub остаётся хранилищем кода** (не «совсем без GitHub»: сервер делает `git pull origin` с GitHub, PR остаются).

## Что сделано (25.10)

- [x] `scripts/ci-local.sh`: backend (одноразовый Postgres, миграции, сборка, `go test -count=1 -v` с `DATABASE_URL`; **падает, если хоть один тест напечатал «DATABASE_URL not set»**), bot (отдельный Go-модуль), frontend (`CI=true pnpm install --frozen-lockfile`, typecheck, lint, test, build), docker (сборка трёх образов, запуск api, `/api/health`). Зелёный на всех четырёх этапах и чистом коде → штамп `.git/ci-local.ok` = sha коммита.
- [x] `scripts/hooks/pre-push` (подключён `git config core.hooksPath scripts/hooks`): push в `develop`/`main` коммита без штампа отклоняется; правки только `docs/`, `graph/`, `*.md` проходят без прогона; обход осознанный: `git push --no-verify`.
- [x] `scripts/deploy.sh dev|prod`: те же шаги по ssh, что `deploy` и `deploy-dev` в `ci.yml` (прод: бэкап обязателен, `git pull`, build, up, health). Отказывает: нет штампа; коммит не на GitHub (хост тянет оттуда); не та ветка; **прод без человека у терминала** (нужно напечатать `deploy prod`; агент без tty запустить не может).
- [x] Проверено 25–26.10: четыре этапа **по отдельности** зелёные на коммите `67e377e`: backend (441 тест, 0 пропущено, 76–159 с), bot, frontend (371 с), docker (69 с); детектор пропуска тестов находит реальное сообщение (9 совпадений без `DATABASE_URL`); отказы `deploy.sh` (не та ветка, коммит не на GitHub) и решения hook (код без штампа: отказ; ветка не develop/main: пропуск; только docs: пропуск) проверены руками.
- [ ] **Не проверено:** один полный прогон `scripts/ci-local.sh` до штампа (первый был остановлен системой при нехватке памяти ночью: docker-этап сорвался на `pnpm install` внутри образа, видимо, пока машина спала; повтор docker-этапа отдельно зелёный). **Реальный деплой этим скриптом ещё не запускался.**

## Что осталось

- [ ] 2. Один настоящий прод-релиз через `scripts/deploy.sh prod` рядом с проверкой «GitHub-деплой тоже не нужен». Только Денис, с его словом. После двух успешных релизов (dev и prod) выключить `on: push` у всего `ci.yml`, workflow оставить как `workflow_dispatch` (запасной).
- [ ] 3. Уведомление в Telegram об успехе или падении деплоя, как в CI (сейчас ответ только в терминале). Токен и chat id из локальной памяти проекта, не из репозитория. `~15 мин · ~60k`
- [ ] 4. Скрипты для e2e-секретов: `E2E_TG_BOT_TOKEN`, `E2E_TG_ID` уже читает `web/scripts/e2e-local.sh` (nl-2 и локальная память), проверить на `deploy.sh dev`. `~5 мин`

## Риски (названы Денису 25.10)

- Локально зелёное ≠ чистая машина: потому скрипт каждый раз поднимает свой Postgres и не доверяет кэшу.
- Принуждение теперь только hook на этом компьютере; `--no-verify` его обходит. На втором компьютере hook нужно подключить заново (`git config core.hooksPath scripts/hooks`).
- Деплой идёт с этого компьютера и его ssh-ключа; компьютер выключен — деплоя нет. Запасной путь: ручной запуск workflow в GitHub.
