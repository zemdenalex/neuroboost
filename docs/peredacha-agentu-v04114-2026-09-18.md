## 2. Цикл работы (одна задача = один проход)

1. Прочитать в плане ровно один `## Task N` и его `Files`/`Interfaces`.
2. Сделать правку **только в перечисленных файлах**.
3. Прогнать гейты (полный список — в `Global Constraints` плана):
   ```
   cd api-go && go build ./... && go vet ./... && go test ./...
   cd bot    && go build ./... && go test ./...
   cd web    && pnpm typecheck && pnpm test --run && pnpm build
   ```
4. Красный гейт = задача не сделана. Не «починить тест», а починить причину.
5. Коммит: конкретные файлы (`git add <путь>`, никогда `-A`), **без со-автора**.
6. Записать результат в `docs/agent-log-v04114.md`: задача · вердикт · что прогнано · что осталось.
   Вердикт — одно из трёх: **СДЕЛАНО / ЗАБЛОКИРОВАНО НА ШАГЕ X / ОПРОВЕРГНУТО СО СВИДЕТЕЛЕМ**.

## 3. 🔴 Красные линии — за них агент не ходит

| Нельзя | Почему |
|---|---|
| **Мерж `develop` → `main`** | это релиз прода, только по явному «да» Дениса; перед выкатом бэкап с проверкой восстановлением |
| **Править существующие миграции** | только новая; номер проверять `ls api-go/migrations/*.up.sql \| wc -l`, а не брать из плана |
| **Считать пустую тестовую базу проверкой миграции** | тестовая строится с нуля и слепа к расхождению формы (gotcha 18) — миграция гоняется на копии прода |
| **Выкатывать бота** | веб едет с `main`, бот — руками на nl-2 (gotcha 19) |
| **Склейка строк в SQL** | только параметризованные запросы pgx |
| **Фоновая горутина без `recover`** | gotcha 9 |
| **Трогать чужие проекты** | работа только внутри `V003 - NeuroBoost` |
