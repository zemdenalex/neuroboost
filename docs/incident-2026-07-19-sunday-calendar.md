## Короткая версия

События **создаются нормально**. POST `/api/events` возвращает успех. Их просто **не видно**,
потому что календарь запрашивает **не ту неделю** — и только по воскресеньям.

Сегодня, 2026-07-19, — воскресенье. Завтра баг исчезнет сам.

## Root cause

`web/src/pages/Calendar/Calendar.tsx:42` на `main` (то, что крутится в production):

```js
monday.setDate(now.getDate() - now.getDay() + 1 + offset * 7);
```

В воскресенье `getDay() === 0`, поэтому `19 - 0 + 1 = 20` → получается **следующий**
понедельник.

| | Диапазон |
|---|---|
| `getEvents` запрашивает | 20–27 июля (следующая неделя) |
| `WeekGrid` показывает | 13–19 июля (текущая неделя) |

Событие, созданное сегодня, попадает в показываемую неделю, но **не попадает в fetch** →
пользователь его не видит → выглядит как «создание не работает».

`WeekGrid` считает понедельник правильно (`getMondayUtcMs`), а `getWeekRange` — нет. Расхождение
проявляется ровно в один день недели.

## Почему симптомы сходятся

- В console нет ошибки — POST действительно **успешен**, клиент ничего не бросает.
- 4 повтора подряд — пользователь пересоздавал, потому что ничего не появлялось.
- «Now doesn't work» — потому что сегодня воскресенье; в остальные дни формула верна.

## Это не регрессия от сессии 2026-07-19

Проверено:
- `origin/main` не двигался (последний коммит `0ab11c2`, 17 июня), последний CI run на `main` —
  23 апреля. **Мои изменения в production не попадали.**
- Push был только в `develop` → auto-deploy на `dev.neuroboost.website`.
- `deploy-dev` делает `pg_dump` с prod-базы, но это **чтение**; пишет в dev-базу.
- Prod и dev полностью изолированы: разные container names (`neuroboost-db` /
  `neuroboost-dev-db`), порты (5432 / 5433), volumes (`db-data` / `dev-db-data`).

## Fix

Уже существует на `develop`: `4308a52 fix(calendar): show the current week's events on Sundays`.
Выносит чистую `computeWeekRange` с канонической формулой `(getDay()+6)%7` (та же, что в
`startOfWeek` и `getMondayUtcMs`), + 2 TDD-теста, включая проверку по всем семи дням недели.

**На `main` этого коммита нет** — вот почему production продолжает падать по воскресеньям.
